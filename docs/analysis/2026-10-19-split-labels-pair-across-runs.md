# 2026-10-19 — 一个标签拆成两条 run，靠接续关系配回来

范围：`pid-plot/src/read.rs::TextSpan`、`pid-plot/src/compare.rs::match_text`，
以及五张图对比的文字数字。上一轮的残差表里最后一类「真东西」是切分：参考图
把 `2"NC` 记成一个 run，我方拆成 `2"` 与 `NC`；也有反过来的一处。两类共 5
条参考 run，本轮全部对上，合计 1213 → 1228，之后又随两条落点修正到 **1231**。

## 为什么不能靠改渲染把字拼起来

拆法不是我方能决定的：PDF 里的 run 边界来自字体切换和字距对（kerning pair），
参考图作者写的东西与我方写的东西各自被切在不同的地方。想要「一个标签」这个
概念，只能在**配对**这一层把接续的 run 认回来。

## 改了什么

1. `TextSpan` 新增 `advance_mm`：沿书写方向的宽度。没有它就只能知道一条 run
   从哪里开始，不知道墨迹在哪里结束、下一条从哪儿接。空格 run 墨迹为零，
   宽度记 0。
2. `match_text` 变两遍：
   - 第一遍照旧：同一个文本、1 mm 以内，一条对一条。
   - 第二遍只处理仍然没配上的参考 run，两个方向都试：
     - 参考一条 ↔ 我方「一条 + 接续的若干条」（`run_chain` + `joined_text`）；
     - 参考「一条 + 接续的若干条」 ↔ 我方一条。
3. 拼接生成两种候选：紧贴（`2"` + `NC` → `2"NC`）与一个空格
   （`B2` + `B5` → `B2 B5`）。参考图两种都出现过，判据仍是**字符串全等**。
4. 接续判据：方向点积 ≥ 0.99；横向偏离 ≤ 0.35 字高；沿行间距取绝对值
   ≤ 0.6 字高；最多 4 条。
   - 间距取绝对值（允许重叠）是被数据逼出来的：B 图的 `2-1/2"` + `LO`，
     字高 3.59 mm、前一条 advance 7.75 mm、后一条 origin 落在 6.32 mm 处，
     **重叠 1.43 mm = 0.40 字高**。单侧下限会把这一对拒掉，B 图就停在
     122/123。

## 计数单位没变

`text_reference` / `text_ours` 仍数 run，不是一个「标签」。所以：

- 一条参考 run 配上一个由 k 条我方 run 拼成的标签：`matched` +1（我方那 k
  条都记为已用）。
- k 条参考 run 共用一个我方 run：`matched` +k，未配对表里那 k 条一起消失。

于是 `matched + 未对上条数 = text_reference` 恒成立，而 `matched` **可以大于
`text_ours`**：A 图是 149 / 148，多出来的那一条正是「参考拆开、我方合成一条」
的那次配对。这不是重复计数，是两侧单位本来就不同。

## 还没解决的

- 只在**一侧**拼接。如果两边都拆，例如参考 `A`+`BC` 对我方 `AB`+`C`，仍配
  不上；语料里没有这种。
- 接续是贪心的：从墨迹末端挑最近的一条，拼接失败后不回溯。更近但无关的
  run 会先被选中，代价是少配一条 —— 宁可少配，不会多配。
- 剩下的 5 条参考 run 不属于这一类：I 图两条电机 `M`（字高 4.55 mm 无字段可
  解释）和三条标题栏 `DWG-…集…`（我方 x 差 17.6 mm）。
