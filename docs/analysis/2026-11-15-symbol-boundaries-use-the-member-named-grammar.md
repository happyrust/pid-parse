# 符号缓存和符号文件里的填充边界按点名成员的语法读（2026-11-15）

> 范围：`.sym` 与图纸 `/JSite*/PSMcluster0` 里的 `0x0013 igBoundary2d`（`decode_igsym_boundary_payload`），以及它画进页面的方式。图纸 Sheet 链上的边界读法没有改结果。
> 工单：#66。证据是文件自己的字节。

## 0. 量到的

同一套语法（环数在载荷 `+18`，每个环是成员数、两个字节、成员，然后锚点、标志字节、引用，一直到载荷末尾）。`0x73` 是 42 字节的椭圆：中心、长半轴向量、轴比、方向字节。圆是长半轴 `(r, 0)`、轴比 1。

| | 活的 `0x0013` | 这套语法读到末尾 | 33 字节的 `0x73` | 旧的 `+18 > 1`、步长 48 的读法单独成立 |
|---|---:|---:|---:|---:|
| `.sym`（774 个互不相同的文件：盘上 645，再加压缩包里盘上没有的） | 256 | 256 | 0 | 0 |
| 缓存（`.pid` 与带着 `/JSite*/PSMcluster0` 的 `.igr`，去重之后） | 200 | 200 | 0 | 0 |

缓存的 200 条与 2026-11-12 那篇探针的数一致：191 条一个环、9 条两个环；成员 89 条线、6 条点列、171 个圆、54 条弧。`.sym` 里另有 5 条点列、215 条弧、106 个圆、505 条线，还有 3 个长半轴不在 +X 上的圆和 2 条真椭圆弧。没有一条 `0x73` 是 33 字节。

那 12 条「`+18 > 1`、按 48 字节一步、每步前面是 `04 01`」的符号记录，全部也是这套语法的两个环，每个环一个圆。48 字节就是「42 字节的圆 + 下一环 6 字节的头」。旧读法把下一环的头当成了分隔，把长半轴的 x 当成了半径。没有一条记录只按那种步长成立、按这套语法不成立。

引用：`.sym` 里点了名的引用都落在同一条链的活记录上（线 `0x00CB`→`0x0018`、圆 `0x00D1`→`0x0059`、弧 `0x00D3`→`0x0061` 或 `0x007E`、点列 `0x00F6`→`0x0084`）。缓存里点了名的也一样，都是线或圆。`XIONGANA2.igr` 那 5 条点列记录的引用数是 0，锚点是 `1e30`——跟 Sheet 上不点名成员的记录一样，文件里没有锚点。

九条双环的缓存记录：

- 八条是插头阀的两个圆（三张换热器图，验收语料里的「换热器 CD」与备份里的是同一份字节的另一份）。外环逆时针、内环顺时针，锚点在两圆之间。半径 0.952 / 0.648 / 0.342 mm，两条记录合起来是三个同心（或差 0.030 mm）的盘。2026-10-16 那篇对照过参考图：每个圆各自实心，不能按 even-odd 挖成环带。
- 一条是 `XIONGANA2.igr` `/JSite19` oid 284：两个点列，内环的形心在外环里、走向相反，引用数 0，锚点 `1e30`。这是外环加孔，跟 `XA-A1` 的双环是同一类，只是文件没写锚点。

旧读法丢掉的 20 条缓存记录：`工艺管道及仪表流程-1.pid` `/JSite7559` 的 8 条（线与圆弧围成的一个环），以及 `XIONGANA2.igr` 里的 12 条（5 条点列，加上弧和线围成的环）。

## 1. 读法

`decode_igsym_boundary_payload` 改成这套语法。`0x73` 进了 Sheet 一侧共用的成员词汇（`igboundary_template_members`），圆仍按 0.25 弧度切弦，与严格读法的 `EF井场` 那个点逐位相同——那条记录的引用不落在 21 字节的尾上，模板读法仍然拒收它，还是原来的读法解出它。

一个环若是单独一个圆，符号体里仍是一个圆，页面上各自实心（插头阀的盘不动）。只有线的环仍是那些线。别的环收成一条闭合折线：圆弧按 0.25 弧度切弦，椭圆弧和 B 样条按它们自己的记录在 Sheet 上的画法采样。两条以上这样的折线用 `boundary_fill_ring` 收成一个环，孔反着走。
