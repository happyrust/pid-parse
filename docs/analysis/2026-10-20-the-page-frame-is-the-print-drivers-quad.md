# 参考的双线图框是出图器的四边形，不是图纸内容（2026-10-20 量）

把两张全页缩略图并排看，最扎眼的结构差是**边框**：参考四周有双道黑框，我方没有。
这一页把它量到底，结论分三层 —— 参考的框是两条四边形笔画（五张图里只有两张有），
图纸里没有任何矩形记录承载它，`read_plot` 早就按 `sheet_edge_mm` 把这类贴边笔画
丢掉了。也就是说：**这不是漏画，是口径**。

## 一、框只在五张参考里的两张上，且是两条描边四边形

PyMuPDF `page.get_drawings()` 里的 `qu` 项：

| 图 | 页面 | 四边形 | 线宽 |
|---|---|---|---|
| I井场 | 1189 × 841 | (0, 0)–(1188.89, 840.91)、(25.06, 9.99)–(1178.90, 830.92) | 0.48 pt |
| 一级闪蒸分离器B | 841 × 594 | (0, 0)–(840.91, 593.85)、(25.06, 9.99)–(830.92, 583.86) | 0.48 pt |
| 一级闪蒸分离器A / 低温分离器A / 换热器CD | 841 × 594 | 无 | — |

一条 path、两个子路径、`S` 描边（`type: "s"`，`closePath: False`），0.48 pt 就是
本页最细的那支笔（0.169 mm）。外框贴满纸边（1188.89 / 1189 = 99.99%，840.91 / 841
= 99.99%），内框左边留 25.06 mm、其余三边留 9.99–10.08 mm —— 装订边 25 mm 的
制图惯例。两条框合计 **8009.1 mm** 的墨：外框 4059.6 + 内框 3949.5。

没有框的三张不是「矢量里有、渲染没画」：300 dpi 光栅后数页面最外 0.6 mm 带内的
深色像素，I 顶边 14 061 / 左边 10 129，B 19 881 / 7 316，A、低温A、换热器CD 全 0。
矢量和像素两路读数一致 —— **三分之二的参考图根本没有边框**。

## 二、图纸里没有矩形记录承载它

`probe_sheet_rectangles` 遍历每张图 `Sheet6` 上解码出的 `igRectangle2d`（`0x0020`）：

```text
cargo run -p pid-parse --example probe_sheet_rectangles -- "<drawing.pid>"
I井场 注采阀组工艺及自控流程图.pid: total 0
```

语料里仅有的 3 条 `0x0020` 在嵌套 `JSite` 的 `PSMcluster0` 里（符号体几何，见
`AGENTS.md`），没有一条落在图页上。所以图框既不是图纸的几何，也不是符号放置 ——
它是参考出图器（或它加载的 `.igr` 图框模板）自己的家具。

## 三、`read_plot` 早就有这条规则

`pid-plot/src/read.rs` 的 `sheet_edge_mm` 丢掉「沿纸边走向、超过页边 90%」的笔画，
理由写在它的文档里：参考把图框存成 PyMuPDF 不计入线项的四边形，我方要是不丢掉同样
的线，对比就会报出参考根本拿不出来的墨。

拿实数验一遍这条阈值：外框 99.99%、**内框 97.0% / 97.6%** —— 两条框的 8 条边全部
过线，全部被丢；页面上真正的内容笔画最长 431.8 mm（I 图），远在阈值内。丢弃的
判定和注释里「real lines stay under 75%」的观察一致，只是这里补上了上界：
95%–100% 这一段确实只有图框。

后果是两侧对称的：参考的框读不进来，我方画的框也读不进来。于是「画上框」这个动作
在判据上换不到任何东西 —— 它只会在三分之二的参考图上变成实打实的多画。

## 四、边框带里**读进来**的那 3 km 是什么

`probe_border_segments` 看的是读进来之后落在页外圈 30 mm 内的笔画：

```text
cargo run -p pid-plot --example probe_border_segments -- "<plot.pdf>" 30
I井场 参考：band 30.00 mm: 107 of 11291 segments，合计 3041.4 mm
  140.04  (1038.86, 64.01) -> (1178.90, 64.01)  stroke 0.169   ← 标题栏横线
  140.04  (1038.86, 23.99) -> (1178.90, 23.99)  stroke 0.169
   99.91  (  25.06,580.98) -> (  25.06,680.89)  stroke 0.169   ← 会签栏竖线
```

这 107 条全是右下标题栏与左侧会签栏的格线，`template_masks` 把它们整块排掉
（I 图 `masked_reference_length_mm` = 3045.0，B 图 3027.2），因此既不进覆盖率、
也不进多画。换句话说：**边框带的墨有两类，一类被 `sheet_edge_mm` 丢、一类被
`template_masks` 排，没有一类留在判据里。**

我方同一条命令读出来是 `0 of 12283 segments`：外圈 30 mm 内一条墨都没有。于是
「参考有图框、我方没有」在缩略图上看的其实就是这一件事 —— 整页家具（双线框、
标题栏格线、会签栏）我方一条不画，而 `compare` 对这三样分别用丢与排处理。
五张图里 `masked_reference_length_mm` 是 3045.0 / 0.0 / 3027.2 / 0.0 / 0.0
—— 另三张的参考在同样两块矩形里没有线墨，所以「没画」在那三张上不是差。

## 五、如果哪天要画框

两条路，都要先改口径再改图：

1. **让读取器认四边形**：`read_plot` 把 `re` / `qu` 展成四条边、取消
   `sheet_edge_mm`。五张图的覆盖率会一起掉 —— I 图的框 8009.1 mm 相当于把分母从
   31 518.7 抬到 39 527.8，覆盖率 0.9989 → 0.7965；B 图从 8304.0 抬到 16 313.1 后
   只剩 0.508。这一步不能和数据管线混着做。
2. **按模板常量画框**：需要先接受「三分之二的参考没有框」这个事实，并且只在
   `template-masks.json` 已经量过的那两种图幅上画。今天不做 —— 它不可测量，
   而当前唯一的相似度判据是 `compare`。

现状（本页不改任何代码，只加两个探针）：

```text
五张图多画 41.8 / 7.6 / 1.5 / 22.9 / 24.6 mm
覆盖率 0.9989 / 0.9998 / 0.9979 / 0.9986 / 0.9993
文字   544/546、151/151、123/123、167/167、249/249
```

## 复现

```text
cargo run -p pid-parse --example probe_sheet_rectangles   -- "<drawing.pid>"
cargo run -p pid-plot  --example probe_border_segments    -- "<plot.pdf>" 30
cargo run -p pid-plot  --example dump_symbol_primitives   -- "<图名>" "*"
python: page.get_drawings() 里 item[0] == "qu" 的项 → 图框的四个角
```

参考 PDF 的 `Contents` 里那条路径是：

```text
q n 0 2383.68 3370.56 -2384.16 re W n
  n 0.48 w
  0 2383.68 m 3370.08 2383.68 l 3370.08 0 l 0 0 l 0 2383.68 l 0 2384.16 l
  71.04 2355.36 m 3341.76 2355.36 l 3341.76 28.32 l 71.04 28.32 l 71.04 2355.36 l 71.04 2355.84 l
  S
Q
```

外框四条边 + 内框四条边，一次 `S`。`71.04 pt = 25.06 mm`、`28.32 pt = 9.99 mm`
—— 就是上表的内框边距。
