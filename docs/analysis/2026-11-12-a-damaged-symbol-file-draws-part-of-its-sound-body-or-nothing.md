# 断了链的符号文件：画完好文件所画的一部分，或者不画

2026-11-12，工单 #67。上一轮（#51）让页面在「放置是从带链故障的库符号体画出来的」时候出声、记账，放置照画；
当时量到画出来的可以是别的墨（压力表多一个 `PG`），第十一次独立审查又量到根流坏了时两个圆、而且一个字都没有。
这一篇是把符号文件一侧改成与图纸一侧同一条规矩之后的读数与依据。

## 结论

- **一个走查。** 符号读取器读 `Sheet*`、`PSMcluster0`、`StyleCluster` 三种流都用 `SheetChain::walk`——图纸自己的
  图纸流、缓存体、样式表用的那一个。每条流读到链立得住的地方为止；符号体的故障表
  （`SymbolGeometry::chain_faults`）就是这个走查对每条流说的话，根 `/PSMcluster0` 在内。
- **读短了的流不由别的图纸顶替。** 画什么由 `SymbolGeometry::displayed` 定：每条流都读全了的文件，画法与以前
  一样；有流读短了的文件，画出来的是完好文件所画的一部分，带着原来的笔、层与图纸；这一部分拿不到时不画，原因
  是三种之一（`SymbolNotDrawn`）：根簇读短了（`ClusterShort`）、作正常视图的图纸读短了而读到的东西一笔都不显示
  （`NothingToShow`）、要按笔画数挑图纸而有图纸读短了（`PickAmongShortSheets`）。
- **没有少读记录的故障照画。** 魔数不对而链走到流尾、流头记的条数比链上的少：符号体与完好文件相同，只出声。
- **页面上**：不画的放置按缺符号处理（图纸自己的放置在 `PaperModel::missing_boxes` 里记一个框——写出端不画它——
  记一项 `symbol_missing`，名字进 `missing_symbols` 并注明「文件在、是坏的」）；文件照旧每条坏流一行 `warning:`、一项 `symbol_file_chain_fault`，
  不画时那一行说「没有画」和原因。
- **符号库**：读短了的副本就是库的答案，不因为它读出来是空的就换下一个根目录里的同名文件。
- 入库的 6 个符号文件与入库压缩包里的 616 个，每条链流、每种损坏（磁盘上 715 种、压缩包里 88 356 种）都守住
  上面几条；改之前同一个扫查在磁盘上有 76 种、压缩包里有 11 515 种图纸损坏画出了完好文件不画的图元。

## 一、符号文件靠什么决定画哪张图纸

`examples/probe_what_decides_the_sheet_a_symbol_file_draws.rs` 把够得着的符号文件读了一遍（`test-file`，这台机器上
`test-file/symbols-full` 是整套参考库）：1 845 个文件（磁盘上 624 个、12 个压缩包里 1 221 个），没有读不了的。

| 读数 | 值 |
|---|---|
| 图纸流 | 3 697 条（4 条在嵌套存储里），全部是立得住的链 |
| 根 `/PSMcluster0` | 1 845 条，全部是立得住的链；嵌套的 122 条也是 |
| `StyleCluster` | 1 967 条，全部是立得住的链 |
| 从链上读出的图层表、视图集与簇走查器读出的 | 每个文件都相同 |
| 一个文件的图纸数 | 1 张 3 个、2 张 1 832 个、3 张 10 个 |
| 作正常视图的图纸数 | 0 张 567 个、1 张 1 201 个、2 张 77 个 |
| 符号体是 | 一张正常视图 961、几张正常视图 14、笔画最多的那张 729、唯一的一张 126、整个体 6、什么都没有 9 |
| 只有流头的图纸 | 314 条 |
| 图纸上被取代的记录（类型字带 `0x8000`） | 1 106 条，其中 660 条是符号读取器会画的类型 |

两件事从这里来：

1. 画哪张图纸取决于**两条流**——图纸自己，和放图层表与视图集的根簇。根簇是普通的记录链（簇走查器从 `+171` 进去，
   跳过前两条记录；读出的表与「按链上的记录起点读」逐个相同），所以它可以、也应该和别的流用同一个走查。
2. 将近一半的文件（729 + 126 个）不是靠视图集、而是靠**数笔画**挑图纸的。一张图纸读短了，它的笔画数就不知道，
   这个挑法在这种时候不能用。

## 二、原来的读取器与图纸读取器在哪里结论不同

| 情形 | 图纸读取器（`SheetChain::walk`） | 原来的符号读取器 |
|---|---|---|
| 类型字带 `0x4000` | 停在这个字上 | 把类型字掩成类别再读，读穿过去，体与完好文件相同 |
| 第一个字不是魔数，链走到流尾 | 照读，出声 | 这张图纸整张不读 |
| 链有停点 | 停点之前的记录照读 | 整张不要（「读一半不如不读」） |
| 根 `/PSMcluster0` | —（图纸的根簇不走这条路） | 经簇走查器：要魔数、要走到最后一个字节，否则图层表与视图集一个都没有；这条流不在故障表里 |

「整张不要」在实践里的意思是把符号体交给文件里的另一张图纸：压力表 `/Sheet6`（它的正常视图，页上是一个圆）一坏，
体只剩 `/Sheet68`，页上是那个圆和一个完好文件不写的 `PG`。根簇一坏，没有视图集说 `/Sheet6` 是正常视图、没有
图层表说伴热那一层不显示，同一个压力表画成两个圆。

解析侧的文档里有一句「停了的图纸什么都没给符号体」（`SymbolGeometry::chain_faults` 的说明与
`tests/sheet_chain_faults.rs` 里那条用例的说明）。对带 `0x4000` 的停点它不成立：链的走查报「停了」，读取器读穿，
体是完整的。两处都改了。

## 三、什么叫「读短了」

`SheetChain::is_short()`：走查在流尾之前停了，或者走到了流尾、但读到的活记录比流头写的少。

后一半是一条流**被齐着记录边界截断**时的样子——走查干干净净走到新的流尾，只有条数说少了记录；也是「流头的条数
多写了一条」的样子，流里没有任何东西能把这两种分开。

**这里与工单的规则 4 有一处出入，照实写在这里。** 规则 4 把「记录数不符」与「魔数不对而链仍走到流尾」并列为
「没有少读任何记录的故障，照画、只出声」。条数**少写**时（流头写的比链上的少）确实没有少读，照画。条数**多写**时
读取器分不清是流头错了还是尾巴上的记录没了；如果按「照画」处理，那么一张被截断的正常视图会照旧退到另一张图纸，
正是这张工单要去掉的事（压力表 `/Sheet6` 截到只剩流头、流头条数不动：原来的画法是圆加 `PG`）。所以多写按读短
处理。它与规则 4 字面不同的范围是：图纸流条数多写而这张图纸**又**不是「读到的东西里有显示的笔画的正常视图」的
时候——磁盘上 12 条图纸流里 4 条、压缩包 1 235 条里 593 条（其中 6 条是少画、587 条是不画），以及根簇条数多写时
（一律不画）。其余的条数多写照画。要改回字面读法只动 `is_short` 一处，代价是上面说的截断情形。第十一次审查
提过一条界线——「链读到的记录数达到流头写的数就算读全」；对走到流尾的流，这里用的就是它。走查停了的流不看
条数，一律按工单规则 2、3 的「停了的图纸」处理（流尾多出几个字节也是：记录一条没少，图纸保有位置，它是有显示
笔画的正常视图时照画，要数笔画挑图纸时不画）。

没有少读的两种：第一个字不是魔数而链走到流尾；流头条数少写。这两种只进故障表，不进 `SymbolGeometry::short`。

**走查没有话说的两种（2026-11-13，集成分支；独立审查 `parse7-review-3f121cd.md` 的应修 S1）。** 一条流一个
字节都没有，`SheetChain::walk` 读成一条空链、没有故障——它把每个字节都读了；一条流根本不在文件里，走查
无从走起。符号读取器原来照走查的话读：图纸清空成 0 字节就是一张没有笔画的图纸，符号体退到另一张图纸
（压力表 `/Sheet6` 清空：圆加 `PG`）；根 `/PSMcluster0` 清空或不在文件里就是没有图层表、没有视图集（两个圆）。
都是这张工单要去掉的画法，而且故障表是空的，页面一个字不说、不记账。同一条流截到 5 个字节是读短、不画、出声，
截到 0 个字节却是照画不出声。

符号文件的链流不管里面有什么都以 8 字节的流头开头（语料里最短的是只有流头的图纸），每个符号文件的根下都有
`PSMcluster0`。所以现在符号读取器把这两种当作读短：一个字节都没有的 `Sheet*`、`PSMcluster0`、`StyleCluster`
进故障表（`StreamChainFault::of_an_empty_stream`，说的是「停在 +0，流比流头短」，与截进流头的流同一句话），
图纸与簇另进 `short`；根下没有 `PSMcluster0` 的文件按根簇读短处理，故障表里是
`StreamChainFault::of_a_missing_stream`（新的停止原因 `NoStream`，说的是 `the file holds no such stream`）。
之后画什么照第四节，一条规则都没有加。走查本身没有改：图纸自己的流是空的时候，它照旧是一条没有故障的空链。

完好的文件不受影响，这是量过的：本机够得着的 6 353 个符号文件（`test-file` 1 845、两处 `pid-test-data` 各
1 932、共享语料 644；审查按内容去重是 774 个）里，没有一条链流是 0 字节，每个文件根下都有 `PSMcluster0`，
没有一个符号体带故障、读短或不画（`examples/probe_what_decides_the_sheet_a_symbol_file_draws`，现在这三样
有一样不是 0 就以非零退出）。

## 四、读短之后画什么

`SymbolGeometry::short` 记三样：读短的 `PSMcluster0`（路径）、读短的图纸、**在第一张读短的图纸之后读的图纸**。
`displayed()` 的规则：

1. 有 `PSMcluster0` 读短 → 不画（`ClusterShort`）。图层表与视图集少了条目，隐藏的层会读成显示的、备用视图会
   读成符号体，补不回来。
2. 没有图纸读短 → 原来的画法，一字不改（正常视图里有显示笔画的那些；没有就挑笔画最多的那张；再没有就整个体）。
3. 否则，能画的图纸是「正常视图、有显示的笔画、而且不是在读短的图纸之后读的」那些，画它们显示的笔画。读短的
   图纸自己如果是这样的图纸，就画链读到的那些笔画——它保有原来的位置。
4. 第 3 步一张都没有 → 不画。有正常视图读短了（或排在读短的图纸之后）是 `NothingToShow`；否则是没有正常视图
   能画、要数笔画，而有图纸读短了，是 `PickAmongShortSheets`。两条退路（笔画最多的那张、整个体）在这里都不走。

**为什么排在读短的图纸之后的图纸不能画。** 两张图纸共有的笔画只留在先读的那张上（读取器先读正常视图）。先读的
那张读短了，后一张上留下来的笔画里就可能有本该留在前一张上的——在前一张的层上，由前一张的视图集决定显示不显示。
压缩包里有这样的文件：把这一条去掉（改动 R2），扫查在压缩包上失败，库内的单元测试也失败。

用入库的三个文件钉住（`tests/sym_file_chain_faults.rs`）：

- 压力表：每条流、每种损坏，画出来的是那一个圆，或者不画。`/Sheet6` 在第一条记录（那个圆）之前停——长度为零、
  类型字带 `0x4000`、类型字越过类别表、截到流头、截进流头——是 `NothingToShow`；根簇读短是 `ClusterShort`；
  其余都是那个圆。
- `Circle.sym`：正常视图 `/Sheet6` 只有流头，圆在没有视图集管的 `/Sheet12` 上，靠数笔画挑中。`/Sheet12` 读短是
  `PickAmongShortSheets`，`/Sheet6` 读短是 `NothingToShow`；没有少读的两种照画那个圆。
- 角式截止阀：`/Sheet6` 13 条记录、9 笔显示的笔画。链依次停在每条记录上，画出来的笔画数是
  0（不画）、1、2 … 9、9、9、9，每次都是完好文件那 9 笔的前几笔。

## 六、样式表读短

`StyleCluster` 给的是笔、填充色与文字样式，不决定画哪张图纸、哪些笔画。它读短之后：

- 符号照画；笔画与文字的图形与完好文件逐个相同（扫查里一个不差）。
- 样式在停点之后、没读到的笔画用默认的笔，填充用默认的颜色——图纸自己的样式表读短时图纸上的笔画也是这样。
- 有一处个数会变：两条边界记录写的是同一块区域、同一种颜色时只画一次（按「图形 + 颜色」去重）；样式表只给出
  其中一条的颜色时两条都画，同一块区域多填一次，一次是默认色。压缩包里 2 个文件、28 种改动是这样
  （`Supply Scope Break.sym` 8 种、`DV-Deluge Control Valve with Flange.sym` 20 种），扫查把它单列成一种结果
  （`Outcome::More`）钉住，并且守住「填充所用的每个图形都是完好文件某个填充所用的图形」。

这一条没有改读取器：工单列的流是各张图纸与根流，样式表读短时用什么笔是另一个决定（丢掉这一笔、用默认笔、还是
整个放置不画），没有替工单做。

## 七、符号库有几个根目录时

`SymbolLibrary` 按次序找根目录（目录在前、压缩包在后），遇到「什么都没有可画」的副本接着找下一个根——同名文件在
一个根里只有文字或连接点、在另一个根里才是画出来的版本。读短了的副本读出来也可能一个图元都没有
（`Circle.sym` 的 `/Sheet12` 停在唯一一条记录上），原来就这样被跳过去，画的是第二个根里的文件，一个字都没有。
别的根里的文件顶替坏了的文件，和别的图纸顶替坏了的图纸是一回事；现在读短的副本结束查找，它就是库的答案
（带着故障，画不画由 `displayed` 定）。`a_damaged_copy_is_not_passed_over_for_another_roots`，先红：故障表是空的。

那条用例只走两个目录。查找里目录一段循环、压缩包一段循环，各有一句「读短的副本就是答案」；独立审查把压缩包
那一句改回去，全部用例照过（建议 N1）。2026-11-13 补了库内的一条
`a_copy_read_short_in_an_archive_is_not_passed_over_for_the_next_source`：两个 `RefData~*.zip`，读短的副本在前
则答案是它（故障表一条、没有图元、`PickAmongShortSheets`），完好的在前则答案是完好的；只凭文件名找时一样；

## 九、没有做的与边界

- **被取代的记录。** 图纸读取器不解类型字带 `0x8000` 的记录（原生读取器跳过它们）；符号读取器一直照解，这次没有
  动。全库 1 106 条，其中 660 条是会画的类型；压力表 `/Sheet6` 上就有两条被取代的文字（解出来是 `NULLNULL`、
  `NULL`，在不显示的层上）。两个读取器在这里不一致，而这不是链故障，改它会动完好文件的画法，要另量。
- **空的图纸流。** 0 字节的流两个读取器都认为没有故障（没有流头可比），符号文件的图纸被清空时看不出来。
  （2026-11-13 符号文件这一侧改了，连同没有根簇的文件，见第三节末。图纸自己的流没有动：走查照旧把空流读成
  没有故障的空链，一张 `Sheet*` 是 0 字节的图纸画出来少了那张图纸的墨而不出声。语料里没有这样的图纸。）
- **只有一张图纸的文件**（126 个）读短时按规则 3 不画。只有一个候选时画停点之前显示的笔画也守得住「只少不多」，
  没有做，照工单的字面。

- **打不开的符号文件**（不是复合文件）照旧跳到下一个根，不在这张工单里。
