# 隔膜执行器的弧盖画在了弦的另一侧（2026-10-20 量）

出图对比里五张图的「多画」按符号归堆，最大的一堆每张都是 `Diaphragm Actuator.sym`
（I 13.9、A 7.1、B 7.1、低温 A 6.8、换热器 CD 14.2 mm）。逐条追下去，那截墨不是
多出来的线，而是**同一段弧画到了弦的另一侧**：我方比参考少画的那一截就在对面，
两张图上每次都是「多画 ≈ 没盖住」。

## 一张图上的读数

I 井场 `(899.18, 486.41)` 处叠了两个 placement：阀体 `2 Way Generic Body Type 1.sym`
和它的执行器 `Diaphragm Actuator.sym`。执行器的拱顶在两张 PDF 里是这样：

| | 弦 | 拱顶 |
|---|---|---|
| 参考 | (895.94, 495.30) → (902.21, 495.30) | 中点 (899.16, **497.84**)，在弦上 2.54 mm |
| 我方 | (896.00, 495.30) → (902.35, 495.30) | 中点 (899.18, **492.76**)，在弦下 2.54 mm |

弦落在 `486.41 + 8.89 = 495.30`，两边一致；拱顶一边在弦上、一边在弦下，正好互相
镜像。物理上拱顶该在弦上（执行器的膜头在阀体上方，阀杆从 495.30 往下接到阀体），
参考那一侧是对的。

## 两个来源说的是同一件事，且都是「弦下」

- **图纸自己的定义缓存**：`PidSymbolDefinitionRef { site: 37311, sheet: 52 }`，执行器
  画的是 `Line + Line + BSpline`。那条 `BSpline` 的极点是
  `(0.003175, 0.00889) → (0.00317499, 0.0078379) → … → (0, 0.00635) → … →
  (-0.003175, 0.00889)`，权重 `1.0 / 0.92388` 交替、knots `[0,0,0,1,1,2,2,3,3,4,4,4]`
  —— 一条从弦（y = 8.89）垂到 6.35 再回来的半椭圆。按数字读，拱顶在弦下。
- **参考库 `.sym`**：同一件符号里那条 `0x007E igEllipticalArc2d`（符号读取器目前
  跳过它，见下）是 `center (0, 0.00889)`、`major_axis (-0.003175, 0)`、
  `ratio 0.8`、`sweep π → 2π`。半轴 3.175 / 2.54，中心就在弦中点上 —— 同一个椭圆，
  按我们现在的角度约定也落在弦下。

也就是说，缓存与库彼此一致，两份都是「弦下」；参考图是「弦上」。差在**角度/扫掠
方向的约定**或者缓存那份 NURBS 的生成方式，不在这张图纸的数据里。

## 为什么这轮不动它

要把它画对，得先把 `.sym` 的 `0x007E` 接进符号读取器（`read_symbol_geometry` 现在
把它记进 `skipped`：`Diaphragm Actuator.sym` 报 `{94: 8, 126: 1}`，`126` 就是
`0x7E`），再定下 `sweep_start / sweep_end` 是逆时针还是顺时针量。两条都缺证据：

- 缓存与库都存「弦下」，说明这不是「某个 placement 被镜像了」——四台执行器里三台
  带 `rot = -π, scale = (1, -1)`（净效果 x 镜像），一台是 `rot = 0, scale = (1, 1)`，
  四台的多画都在同一处，所以与 placement 的镜像无关。
- 单改角度约定会同时翻掉缓存体里所有 `0x7E`（A01 的椭圆封头那几条已经在测试里），
  没有一份参考图能证明它们现在是错的。

这一轮只记录：`examples/probe_body_at`（某个纸面点最近的符号实例与它画出的全部
体图元）、`examples/probe_definition_arcs`（缓存体里每条弧的中心/半径/起止角）、
`examples/probe_sym_elliptical_arcs`（`.sym` 里被跳过的 `0x7E`，以现有解码器读出）。
