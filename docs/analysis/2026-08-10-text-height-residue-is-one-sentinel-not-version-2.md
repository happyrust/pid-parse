# 字高残余不是 version-2 路径，是一条被复制到每张图的 0.01″ 模板样式

> 日期：2026-08-10
> 范围：`pid-parse`
> 结论类型：**负结论 + 现状重测**——Phase 39 给缺口 D 定的病因不成立，
> 且缺口本身比计划里写的小一个数量级。
> 前置：`2026-08-04-jstyletextchar-native-reader-confirmed.md`（version 3 读取序）、
> `docs/plans/2026-08-07-phase39-render-gap-triage-cn.md`（D/E/F 分诊）
> 工具：`examples/probe_text_height_fallback`

## 0. 一句话

Phase 39 S1 打算去读 `0x002C` 的 version-2 序列化路径，理由是「回退桶多半落在
version 2 上」。**这条理由被两次实测否掉**：记录里根本没有逐条写版本号，而全语料
25 条回退**没有一条**是布局异常——它们指向的三条 `JStyleTextChar` 在四张图里
**逐字节相同**，都把字高写成 `0.254mm`（= 0.01″）。缺口 D 不是解码欠账，
是「文件就是这么写的，而这个值不可能是真字高」。

## 1. 版本号不在 payload 里

`sub_100323A0` 用 `jengine_1076(stream, &CLSID, …)` 取版本再分发，所以「版本」这件事
本身是坐实的。但它是不是**每条记录**写一次，从来没人在真流上看过。

用**对照法**定位：格式指南已按 native-reader 把三个族钉死在各自的版本上
（`0x002C`/`0x002D` = version 3，`0x002E` = version 2），那么 payload 前段里
**在前两族恒读 3、在第三族恒读 2** 的那一列就是版本号；没有这样一列，就是没写。

全语料 502 条记录（`0x002C` 203 / `0x002D` 182 / `0x002E` 117）的 `+0..+13`：

| 列 | `0x002C` | `0x002D` | `0x002E` |
|---|---|---|---|
| `+0` | 108 个值 | 98 个值 | 69 个值 |
| `+1` | 5 个值 | 5 个值 | 32 / 36 |
| `+2 .. +11` | 恒 0 | 恒 0 | 恒 0 |
| `+12` | 1 / 2 | 1 / 2 | 恒 1 |
| `+13` | 恒 0 | 恒 0 | 恒 0 |

**没有任何一列携带各族已知的版本号。** `+12` 最接近版本号的形状（小整数、取值少），
但它在 version-2 的 `0x002E` 上恒为 `1`、在两个 version-3 族上是 `1/2`，与版本正好对不上
——它是 `style_link` 模块文档里那个 dash index 字段，不是版本。

**推论**：版本来自流/文档级的 schema，不在记录里。所以「这条记录是 version 2 还是 3」
**在文件侧不可判定**，`style_link` 也就无从按版本分派。要读 version-2 路径，得先找到
一份真的用 version 2 写的 `0x002C`——本语料没有证据表明存在这样的记录。

## 2. 回退桶实测：25/184，全是同一个值

把每条 `igTextBox` 按 `style_link` 的两跳逐条判，失败归因到**失败的那一跳**：

| 图 | 文字记录 | 解出 | 字高被拒 | 其它失败 |
|---|---:|---:|---:|---:|
| DWG-0201GP06-01 | 45 | 44 | **1** | 0 |
| DWG-0202GP06-01 | 45 | 41 | **4** | 0 |
| 工艺管道及仪表流程-1 | 43 | 27 | **16** | 0 |
| D06 | 4 | 4 | 0 | 0 |
| A01 | 2 | 2 | 0 | 0 |
| DWG-0202（publish 副本） | 45 | 41 | **4** | 0 |
| **合计** | **184** | **159** | **25** | **0** |

「其它失败」那一列全零，这本身是个结论：**`index` 没有指空的、段落样式没有不指字符样式的、
被指的字符样式没有缺席的。** 两跳链路本身 184/184 走通，唯一的失败模式是最后那个
字高字段被拒。

25 条被拒记录读出的 `+42` **全部是 `0.000254 m`**，一个不差。

## 3. 计划里的占比写错了一个数量级

Phase 39 §1 写「DWG-0201 字高分布 `3.175×21 / 2.5×9 / 2.464×3 / 1.5×2 / 3.5×2`，
其中 **`2.5×9` 仍是 ISO 3098 回退**」。

实测 DWG-0201 解出的字高分布是
`1.5×2 / 2.464×3 / 2.5×10 / 2.54×1 / 3.175×26 / 3.5×2`——**2.5mm 是这张图真写出来的值**，
写了 10 次。OCS 侧 `PID-TEXT` 上那 9 条 2.5mm 里，**至多 1 条**是回退（这张图只有 1 条被拒），
其余 8 条是图纸自己声明的 2.5mm。

（两侧条数对不上是正常的：OCS 丢掉空文本记录，符号内部文字也不进 `PID-TEXT`。）

所以缺口 D 的真实规模是 **DWG-0201 1/37**、全语料 **25/184**，而不是「每张图约四分之一」。
真正受影响的是**工艺管道及仪表流程-1**：43 条里 16 条回退，占 37%。

## 4. 那三条被拒的样式是同一条

四张图里被拒的字符样式（DWG-0201 的 id 53、DWG-0202 的 id 39、工艺的 id 40），
把身份字段 `+0..1`（句柄）与 `+14..17`（样式 id）排除后，**80 字节逐字节相同**：

```text
5C 20 00 00 00 00 00 00 00 00 00 00 01 00 | 35 00 00 00 | 00 00 00 00 00 00 00 00
02 20 00 00 09 04 00 00 00 00 00 00 00 00 00 0D
B2 81 74 B1 69 A5 30 3F   <- +42，0.000254 m
00 ... 00 05 00 41 00 72 00 69 00 61 00 6C 00   <- "Arial"
```

同一个 `+26 = 0x2002`、同一个 `+30 = 0x0409`（en-US）、同一个字体名、同一个字高。
三张互不相干的图不会各自凑出同一条 80 字节记录，**这是从共享参考数据里拷进每张图的
同一条模板样式**。

顺带否掉一个显然的猜想：`+26`（version-3 写序的第一个类字段 `this+396`）不是判据。
全语料它取 25 种值，`0x2002` 这一个值上就有 9 条字高正常、8 条被拒——它是位掩码
（`0`/`1`/`2`/`3`/`8`/`0x10`…/`0x2000`…/`0xFFFF`），不是版本也不是引用。

## 5. 字高没有第二个来源

被拒的这 25 条是真画在图上的位号（`WWWATER0101100 M`、`ODOIL020150 MM1.`、`1E01`…），
它们总得有个高度。两个可能的备选来源都实测否掉：

- **段落样式里没有。** 扫 `0x002D` payload 全部 `f64` 窗口，落在 `0.5..20mm` 制图区间的：
  被拒记录的段落样式 **0 个偏移命中**（解出记录的段落样式上也只有 1 条在 `+82` 偶然命中）。
- **文字记录自己没有。** `igTextBox` 第三个尾部 double（解码器注为「常为 1.0，缩放或标记」）
  在被拒与解出两侧分布同形——被拒 `1.0×14 / ±0×11`，解出 `1.0×127 / ±0×30 / -1.0×2`。
  它不区分两者，也就不是缩放系数。
- `pid-parse` 的 `IgTextBoxEmitter` 本来就恒发 `height: 0.0`，几何侧从不携带字高。

## 6. 结论与下一步

**`style_link` 现在的行为是对的，不需要改。** 拒收 `0.254mm`、让消费方保留自己的默认值，
正是面对「文件写了一个不可能是字高的值」时唯一诚实的做法。把它按制图惯例填成 2.5mm
才是错的——那会把一条**没有解出来**的记录伪装成解出来了。

**缺口 D 应当从「解码欠账」改判为「已正确处理的已知语义空洞」**，并补上一件事：
**让回退可见**。现在 25 条位号被画成 2.5mm，日志里一个字都没有；`OpenCADStudio` 的
`report_import` 已经会按名字报告解不出来的图形族，字高回退应当同等对待。

`0x002C` version-2 路径**不再是关键路径**：它既无法从文件侧判定，也解释不了任何一条回退。
若将来仍要读，理由只能是别的。

**翻案的最便宜路径**（留给以后）：`0.254mm = 0.01″` 是 1/100 英寸，形状像
「未设置 / 取默认」的哨兵（与 `+34` 那个 `-1` 哨兵同一类惯用法）。要证实，得读
**消费侧**——`rad2d` / `radsrvitem.dll` 拿到这个字高之后怎么用——而不是 `style.dll`
的 version-2 序列化器。已排除的一条：`style.dll` 的 `.rdata` 里**没有** `0.000254` 这个常量，
`0.01` 有三处但被两个与文字无关的函数读走。

## 7. 复现

```powershell
cargo run --example probe_text_height_fallback
```

A 段定位版本列，B 段按失败的那一跳给回退归因，C 段把被拒记录与同长度的正常记录并排
逐字节比，D 段把 `+26` 与字高可用性交叉制表，E 段扫备选字高来源。
