# 一整页只用一支黑笔：参考出图的墨色与三档笔宽（2026-10-20 复量）

出图对比一直只量几何（覆盖率、多画、文字落点），颜色和笔宽从来没进过判据。
把两张 PDF 在同一处按 6 倍放大并排看，最大的一处不同是**颜色**：参考是纯黑
单色图，我方按图纸样式画出橄榄、绿、暗红三种墨。这一页把这项差量出来，并给出
一套可以逐页验证的替代规则。

## 参考：五张图都只有黑墨

用 PyMuPDF 逐页读 `get_drawings()` 与文字的 `color`：

| 图 | 描边 | 填充 | 文字 | 描边宽度 |
|---|---|---|---|---|
| I井场 | 696 黑 + 16 白 | 80 黑 | 全黑 | 0.48 / 0.96 / 1.92 pt |
| 一级闪蒸分离器A | 109 黑 + 3 白 | 14 黑 | 全黑 | 同上 |
| 一级闪蒸分离器B | 144 黑 + 3 白 | 28 黑 | 全黑 | 同上 |
| 低温分离器A | 112 黑 + 2 白 | 23 黑 | 全黑 | 同上 |
| 换热器CD | 257 黑 + 2 白 | 11 黑 | 全黑 | 同上 |

三档宽度是 **0.48 / 0.96 / 1.92 pt**，即 0.169 / 0.339 / 0.678 mm，与
`docs/analysis/2026-10-17-monochrome-plot-three-pen-table.md` 从 OpenCADStudio
那一侧量到的笔宽表逐位相同。那一页的结论「参考出图器跑的是等价单色 CTB」
现在在**颜色**上也成立：不是「彩线用细笔」，而是整页一支黑笔。

|---|---|---|

| | 绿 `(0,128,0)` | 1018 |

宽度正好是图纸声明的 ISO 128 阶梯（0.13 / 0.18 / 0.35 / 0.70 mm）乘 `Tf`
换算，四条；参考三条。颜色是图纸样式的屏幕色，参考一张都没有。

## 规则

`pid-plot/src/write.rs` 里两处：

- `PLOT_INK = [0, 0, 0]`：每条描边状态与每次填充都用它，不再读
  `PaperStroke::rgb` / `PaperShape::Fill::rgb`。模型里仍保留颜色（它是解析
  结果，也是以后要画彩图时的依据），页面不画。
- `pen_width_mm(declared)`：按实测锚点把声明宽度并到三支笔 ——
  `≤ 0.30 mm → 0.169`、`≤ 0.55 mm → 0.339`、其余 `→ 0.678`。边界取的是
  07-17 那页的三个锚点：标题栏 0.25 mm 规则线印成细笔，0.50 mm 的符号描边
  落在中笔，0.70 mm 的工艺主线落在粗笔。非法或非正的声明宽度走中笔。

## 复量

五张图重出后（`pid_plot <drawing.pid> <out.pdf>`）逐页读回：

| 图 | 描边色 | 填充色 | 文字 | 宽度分布 |
|---|---|---|---|---|
| I井场 | 全黑 ×3048 | 全黑 ×66 | 全黑 | 0.48 ×1111 / 0.96 ×1729 / 1.92 ×208 |
| A | 全黑 ×553 | 全黑 ×14 | 全黑 | 124 / 370 / 59 |
| B | 全黑 ×459 | 全黑 ×14 | 全黑 | 112 / 307 / 40 |
| 低温A | 全黑 ×654 | 全黑 ×23 | 全黑 | 243 / 367 / 44 |
| 换热器CD | 全黑 ×1114 | 全黑 ×11 | 全黑 | 321 / 714 / 79 |

与参考的**墨色表与笔宽表完全一致**（条数不同是另一回事：我方仍在一些地方把
一条路径拆成几段，见下）。几何判据一条未动：五张图的覆盖率仍是
0.9973–0.9992、多画仍是 8.6–55.7 mm、文字仍是 544/546、151/151、123/123、
167/167、249/249 —— 颜色与笔宽不进 `compare` 的度量，这是有意的：几何门限
不因为换墨而放松。

## 仍然不同的两处（与本页无关，列出以免误读）

- **两条电机 `M`**：参考 `Tf` 12.9 pt（4.551 mm），我方 5.79 pt（2.043 mm =
  `.sym` 样式 2.54 mm × 放置缩放 0.804）。12.9 pt 既不在 `.sym` 的
  `StyleCluster` 里，也不在图纸的样式表（2.46 / 2.47 / 2.54 / 3.18 / 3.53）
  或任何 8 字节处（`0.0045508` / `0.0056602` / `12.9` 在 `.pid` 里 0 次），
  所以它不是「还没找到的字段」。比值 4.551 / 2.54 = 1.7917 也解释不了
  同图其余 12 条符号标签（参考 8.25 pt = 2.91 mm）。
- **参考的白色描边**：每页 2–16 条，都是 0.48 pt、约 0.7 × 1.5 mm 的小勾
  （符号内部的留白 / 小十字），我方不画。量级远小于上面两项，暂不追。

## 验证

- `pid-plot/tests/write_five_drawings.rs` 的 PyMuPDF 检查新增三项断言，跑在
  五张**真实**出图结果上：每一笔描边、每一处填充、每一个字的颜色都必须是
  `0 0 0`，且出现的宽度只能是 0.48 / 0.96 / 1.92 pt。
- `pid-plot/src/write.rs` 新增 `declared_widths_snap_onto_the_three_plot_pens`
  （阶梯四档 + 三档边界 + 非法值）与 `the_page_is_plotted_in_the_three_pens`
  （一条 0.13 mm 与一条 0.70 mm 描边写回后只剩 0.17 / 0.68 mm 两个宽度）。
- 改前改后的几何读数在 `plot_compare_all` 上逐位相同。
