# 模板文字的字宽写在样式里：`JStyleTextChar +52`

日期：2026-11-07

## 结论

`JStyleTextChar` 盘上 `+52` 的 u16 是字宽，单位是字体自身推进量的千分之一。
`style.dll` 把它除以 `1000.0` 写进 Metrics，并且不乘放置缩放（字高 `+368`、`+390` 都乘），
所以它是比率，不是长度。

- `CPE-SQ-A0/A1` 与 `CPECCHB-SQ-A2` 模板里所有 SimSun 样式都写 `800`。参考图把这些字排成
  0.765…0.791 em，也就是写进 writer 的实测常量 `PLATE_TEXT_ADVANCE = 0.78`。
- A2 会签栏修改记录格（`A$C40D91A4B.sym`）的样式 8270 写 `1000`。参考图按整 1 em 排：
  `修改`、`审核`、`日期`、`页次`、`次数` 都是 10.50 mm，`修改号` 15.75 mm。以前我们一律按 0.78 排，
  只有 8.19 / 12.28 mm。

writer 现在读这个字段（`furniture_advance`）：`800` 和缺省仍用 0.78，其它值按 `w/1000` 排。
0.8 和 0.78 的差额来自出图端，记录里推不出来，所以 `800` 继续用实测值。

## IDA 证据（`style.dll`）

- `IJStyleTextCharImp` 位于对象 `+80`，字段在 `this+376`（盘上 `+52`，u16）。
  setter 是虚表槽 7 `sub_100310E0`，没有检查；getter 是槽 23 `sub_1002FC10`，原样返回；
  Equals（槽 21 `0x10031C10`）按整数比较。
- 唯一使用点 `sub_10031760` 写 `Metrics+16 = word / 1000.0`。全库只有这一个 `1000.0` 常量（`0x100a1f08`）。
- `this+380`（盘上 `+54`）是 f32，写进 `Metrics+24`，同样不乘缩放。这次没有用到它。
- Metrics 结构交给 jengine.dll 的 font manager 绘制，下游怎么变成推进量没有对应的 IDB，**未确认**。
  「字宽」这个名字是由数值和数据流向推断出来的，下面的测量支持这个推断。

## 语料分布

盘上 `+52` 的取值：0、784、800、813、968、999、1000、1001。
`.pid` 自身的样式几乎全是 0（字段为 0 时我们当作未声明，按 1 em 排，和以前一样）。

## 测量

`pid-plot/examples/probe_which_width_a_template_label_letters_at.rs`：给出参考 run 推进量除以我方推进量的
比值，按模板/图纸、字体、字高和 `width_permille` 分组。

A2（`集注站 轻烃分离器I…`）：

| 组 | 条数 | 改前 ref/ours | 改后 |
|---|---|---|---|
| SimSun 3.535 `w1000`（修改记录格） | 6 | 1.282 | 1.000 |
| SimSun 3.535 `w800` | 20 | 0.991 | 0.991 |
| SimSun 4.242 `w800`（`hqz.sym`） | 6 | 0.981 | 0.981 |

A0 `I井场`、A1 `空冷器A` 的模板文字全部是 `w800`，前后不变（0.981…1.011）。

## 剩下的偏差

A2 会签栏和标题栏的 **线条** 本身相对参考整体偏 (−0.23, −0.57) mm，图纸自己的线只偏
(+0.15, 0.00)。这和字宽无关：A2 的 `igSmartFrame2d` 载荷 `+196/+204` 存着 (0.388, 0.566) mm，
A0/A1 的同一位置为 0。会签栏文字沿书写方向剩下的 −0.6…−0.8 mm 主要来自这里，另作一项修。
