## 一、模板标题 `华北油田苏桥储气库群`（3 对：I、L M、一级闪蒸分离器B）

### 查了什么量

`pid-plot/examples/probe_template_title_width.rs` 对 11 张图各取这一条 run，把整串宽差拆成三项：
`Tm` 的横向缩放 `sx`、串内字距 `Tc`、末字自身的自然宽。三项按「其余两项保持参考值」单独计算，
残差 = 实测宽差 − 三项之和。

```text
cargo run -p pid-plot --example probe_template_title_width
```

| 图 | `sx` 参考 / 我方 | `Tc` 参考 / 我方 | 整串宽差 | 拆解 |
|---|---|---:|---:|---|
| I / JK / LM / FlashB / AirA / AirB / AirC（7 张全同） | 0.7420 / 0.7429 | +0.5740 / +0.5744 | +0.0532 mm | 缩放 +0.0524（98%）、字距 +0.0008、末字 +0.0051、残差 −0.0051 |

每一对 9 个 gap 的实测步长：参考 `12.892 pt`（27 px），我方 `12.907 pt`（27 px）。
`12.892 / 12.907 = 0.99884`，正是 `0.742 / 0.7429`。

### 排除的假设

- **不是字距规则**：`Tc` 只解释 0.0008 mm（1.5%），且两侧的 9 个 gap 逐个相等（都是同一个 `Tc`）。
- **不是末字自然宽**：0.0051 mm，且这一项与 `sx` 的符号相同、被残差抵掉，不是独立原因。
- **不是竖直方向**：锚点偏差 `0.0185–0.0486 mm`，`down_mm` 在 0.005–0.018 mm，起点两轴都落在
  1/150 in 网格上（`probe_why_paired_labels_miss_the_reference` 的 `model_start_mm` 与
  `ref_start_mm` 差 0.01–0.03 mm）。普查把它归进 `line-metrics` 只是因为宽度越线，竖直没有问题。
- **不是缺一条「模板字按 800 排」的规则**：我们的 `permille_scale` 给出 `0.7429`，
  而 `13 / 17.5 = 0.742857`；参考写 `0.742`。两个值只差 0.0009，无论参考那一位是三位截断
  还是它自己算出的另一个数，都不是本 crate 的字距规则能补的——同一串里 9 个 gap 两侧逐项相等。

### 为什么不修

参考图写 `0.742 0 0 1 Tm`，我们的写出器写全精度 `0.7429`。要让两者相同，得把每个文字图元的
`Tm` 横向缩放都截到三位小数——那会改掉 11 张图每一页的 PDF 字节，属于「改画法」，且违反
`AGENTS.md` 的不变量 I1（71 页字节对照）。收口记录已经把同一现象登记为 `template-scale`
（40 对）的「源侧（出图驱动的写出值）」，本类是同一条写出规则，不另开修法。

## 二、空冷 A/B/C 的 `SP:`（3 对）

### 查了什么量

`pid-plot/examples/probe_sp_colon_step.rs` 把 11 张图上每一条 `SP:` 记录并排，读两侧每个字形的
起点（以 150 dpi 像素计）、步长、`Tc`、`Tm` 横向缩放，并从 `.pid` 重新解析记录本身的
锚点码、段落对齐、字距设置。

```text
cargo run -p pid-plot --example probe_sp_colon_step
```

| 图 | 参考步长 | 我方步长 | `lpDx` 模型 | 参考 `Tc` | 我方 `Tc` |
|---|---|---|---|---|---:|
| I / JK / LM / FlashA / FlashB / ColdA（6 张） | `11+11` | `11+11` | `11+11` | 0 | 0 |
| AirA / AirB / AirC（3 张） | **`11+10`** | `11+11` | `11+11` | **−0.240** | 0 |

9 张图的记录完全同形：值 `"SP:"`、锚点码 `0x05`、段落 `Left`、字距 `Uniform/spacing 1`、
字高 2.54 mm、宋体、无框。参考的冒号步长在两组之间差整 1 px（0.1693 mm）。

### 排除的假设

- **不是 `lpDx` 模型算错**：模型给 `11+11`，与 6 张参考图逐像素相同；`S`/`P`/`:` 在宋体 256 单位
  字面里都是 36（`a8 = 2.54 mm / 49.2`），两步的连续值都是 10.976 px，四舍五入都是 11。
- **不是字距规则**：参考的 `Tc` 是 −0.240 pt，不是 0；但它把 `SP` 与 `:` 拆成两个文字对象写：
  AirA 的流里是 `1 0 0 1 1095.36 1321.92 Tm 0 Tc <00530035> Tj` 再
  `1 0 0 1 1105.44 1321.92 Tm <0054> Tj`，冒号在离串起点 `10.08 pt = 21 px` 处；
  I 井场同一条标签是 `… 2240.64 1989.12 Tm <005B0035> Tj` 再 `… 2251.2 1989.12 Tm <005C> Tj`，
  冒号在 `10.56 pt = 22 px` 处。所以那 1 px 是**冒号自己那次 `Tm` 取整**的结果，不是串内字距。
- **不是记录差异**：9 张的 `igTextBox` 字节与解析出的样式逐项相同（探针打印的 `record` 列逐字相同）。
- **不是页面尺寸**：三张空冷图都是 A1（841×594），与另 6 张同幅面，`device_scale` 相同。

### 为什么不修

要复现，就得把 `SP:` 拆成 `SP` + `:` 两个文字对象、各自取整——这会改三张图的 PDF 字节（画法），
而收益是把 3 对残差从 1 px 变成 0。同一现象在普查里已经归为 `chain-quantization` 的近亲
（两个落点各自取整），源侧。

## 三、A2 的两条 `仪表风管线`（2 对）

### 查了什么量

`pid-plot/examples/probe_a2_device_grid.rs` 取 A2 上全部「`0x48` + 仿宋」的文字记录，把每条记录的
插入点按验收门禁同一个 `Fit` 映射进参考图的坐标，再量参考与我方各自第一个有墨字形的基线
落在插入点下方多少。

```text
cargo run -p pid-plot --example probe_a2_device_grid
```

```text
page: reference 593.999 × 420.000 mm, ours 594.328 × 420.566 mm
fit: scale 0.9999872, translation (+0.1601, +0.0018) mm, within threshold true

value          anchor  line    height   model    reference  ours     ref-model  box w×h mm    grid
低压放空总管    Left    Middle  2.469   +1.3321   +1.2099   +1.3321   -0.1221  42.009×4.034  on
低压放空总管    Left    Middle  2.469   +1.3321   +1.2099   +1.3321   -0.1221  42.009×4.034  on
仪表风管线      Left    Middle  2.469   +1.3321   +1.1343   +1.3321   -0.1978  42.009×4.034  on
仪表风管线      Left    Middle  2.469   +1.3321   +1.1343   +1.3321   -0.1978  42.009×4.034  on

reference minus model, over the 4 labels of the family: mean -0.1600 mm, sd 0.0378 mm, range -0.1978 … -0.1221
```

四条记录的锚点码、字体、字高、段落、字距**全部相同**，框也相同（宽 42.009 mm、高 4.034 mm）；
参考给的基线落点却有 `1.1343` 与 `1.2099` 两个值，互差 0.0756 mm（0.45 px），且都比我方的
`1.3321` 高。

### 排除的假设

- **不是框高**：四条记录的框完全相同（`42.009 × 4.034 mm`），落点却差 0.0756 mm。
  这一条直接否掉「`Middle` 该按框高中线取」的假设——框一样、落点不一样，任何只读框高的公式
  都会给四条同一个值。
- **不是锚点码**：都是 `0x48`，按 `TextLine::from_paragraph` 在非升部行距下读 `Middle`。
- **不是字体或字高**：都是仿宋、2.469 mm、`Cap` 基准。
- **不是段落对齐或字距**：都是 `Left` / `Uniform spacing 1`。
- **不是页面网格**：A2 的 261 条参考 run 起点**全部**落在 1/150 in 网格上（`261/261`），
  所以「A2 不适用网格」这条旧口径是错的——但网格只能解释 ±0.085 mm，
  解释不了 0.198 mm。
- **不是 `Fit` 的缩放/平移**：`scale = 0.9999872`、`translation = (+0.1601, +0.0018) mm`，
  在阈值内；探针已把插入点映射进参考坐标后再量，页幅差（594.328 vs 594.000）不再混进竖直读数。
- **不是水平**：宽差 `+0.0002 mm`，`along` 偏差逐像素相同；这一对只在竖直上越线。

### 为什么不修

四条理由：

1. **整个家族都不对，不只是这两对**：A2 上同族的 4 条标签平均偏 −0.1600 mm、标准差 0.0378 mm、
   范围 −0.1978 … −0.1221 mm。要修就得给「A2 的 `0x48` 仿宋」找一条竖直线规则，而参考给同形记录的
   落点自己就不一致（差 0.45 px），一条固定规则对不上。
2. **A2 的复核是另一条线**：收口记录把 A2 的竖直问题连同「仪表簇偏移 ~16.9 mm」一起列为 A2 复核，
   本 mission 的「不在本单」也写了 A2 的源侧项。
3. **没有可证的规则就不动**：改 `Middle` 的取法会影响 11 张图的每一处 `Middle` 标签（数千条），
   而证据只支持「A2 这 4 条与模型差 0.12–0.20 mm」，不支持任何替代公式。
4. **最像的那条假设已被自己的读数否掉**：`model.rs:2959-2984` 的竖直分支仍按 anchor code 对字高取，
   只有水平用了框宽。但四条记录的框完全相同（`42.009 × 4.034 mm`），参考落点却分成两组，
   所以「`Middle` 改成按框高中线」只会把四条一起平移，不会把它们分开——修了也对不上。

## 三个探针的共同读法

`pid-plot/examples/support/glyphs.rs` 是三个探针共用的字形读回：它按 `read::read_plot` 的同一套
解释器取每个字形的起点、`Tm` 横向缩放、字体名与自身前进，再按 `TextSpan` 的原点把字形归回 run。
放在 `examples/support/` 而不是 `examples/` 根，是为了不成为 cargo 的独立 target（cargo 只认
`examples/*.rs` 与 `examples/*/main.rs`），探针用 `#[path = "support/glyphs.rs"]` 编进来。
