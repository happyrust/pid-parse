# 「几何 → 线样式」的链路：三个候选全部排除

> 日期：2026-08-04
> 范围：`pid-parse`
> 结论类型：**negative note**——三个候选都不成立，链路仍未找到。
> 前置：`2026-08-04-jsl-simple-line-style-weight-colour.md`
> 工具：`examples/probe_geometry_style_link`

## 1. 问题

线宽与颜色的**存放位置**已经定了（`0x002E` payload `+34` / `+50`），但**哪条线用
哪个样式**还不知道。文本没有这个问题：`igTextBox` 的 trailer 自带样式 id
（Phase 35-D）。`igLine2d` 没有——它 50 字节字节全额入账。

判据很明确：**候选字段的取值必须落在该图 StyleCluster 实际定义的线样式 id 集合里，
且要覆盖绝大多数线。**

两张图的 id 集合：DWG-0201 有 25 个线样式（id 1..85），工艺有 23 个（id 1..67）。

## 2. 候选一：`0x00FA` Dependency Object —— 排除

它是每个 Sheet 流里最多的记录，且带两个 OID 引用，看上去最像。实测：

| 图 | 依赖记录数 | 其中引用到 `igLine2d` 的 | 图里的 `igLine2d` 数 |
|---|---:|---:|---:|
| DWG-0201 | 135 | **4** | 24 |
| 工艺管道 | 125 | **26** | 218 |

**覆盖率根本不够**——218 条线只有 26 条依赖记录提到，不可能承载逐线样式。

而且在那些确实引用了线的记录里，「取值落在 id 集合内」的 tail 偏移是散的
（`+33` `+51` `+124` / `+113` `+35` `+89` `+101` `+41` `+53` `+59` `+65`），
命中数 1/4、10/26、8/26……**没有任何一个固定位置**。在 23–25 个值的 id 空间里，
小整数偶然命中本来就常见，这就是噪声的样子。

## 3. 候选二：`igLine2d.sub_type_word`（payload `+12`）—— 排除

`sheet_records.rs` 记录它「见过 0x0010, 0x0001, 0x0065, 0x0032, 0x0023, 0x001F,
0x002B，语义未解」，取值范围与 id 空间重合，所以值得一试。

实测**两张图上它都恒为 16**：

| 图 | distinct | 落在 id 集合 |
|---|---|---|
| DWG-0201 | `[16]` | 24/24（但 16 恰好在集合内） |
| 工艺管道 | `[16]` | 0/218（16 不在该图集合内） |

**恒定值不携带逐线信息**，DWG-0201 那个 24/24 是巧合，不是命中。排除。

（顺带修正一处：`sheet_records.rs` 那条注释列的多值取值范围，在这两张图上没有复现，
`sub_type_word` 只见到 16。注释所依据的语料需要复核。）

## 4. 候选三：`igLine2d.index`（payload `+14`）—— 排除

样式记录的 id 就在 `+14`，所以几何记录的 `+14` 值得一试。实测**两张图给出相反结果**：

| 图 | distinct | 落在 id 集合 |
|---|---|---|
| DWG-0201 | `[43, 50, 86, 101]` | **0/24**（86 与 101 超出该图最大 id 85） |
| 工艺管道 | `[1, 31, 39]` | **212/218** |

工艺那个 212/218 单看很像，但 **3 个取值落进一个 23 元集合本来就有约 4% 的偶然概率**，
而 DWG-0201 直接给出反例（超出 id 上限的 86 / 101）。**一张图成立一张图不成立的规则
不是规则。** 排除。

**这一条特别值得记下来**：如果只看工艺那张图，很容易把 212/218 当成结论。跨图纸
交叉验证是这里唯一能挡住误判的东西。

## 5. 还没测的候选

1. **`0x0010` 子记录**。全语料 638 次命中，现有描述是「嵌在其他记录里的属性片段」。
   如果线样式是随几何一起存的，最可能在这里。**这是下一个该测的。**
2. **样式按图层/level 生效**而不是逐实体。若如此，就该有一张 level → style 的表，
   而不是每条线带 id。
3. **`0x0030 JStyleOverride`**（已解码，Sheet 流里有）本身就是「覆盖」语义，
   也许正常情况走默认样式、只有例外才写 override。这能解释为什么找不到逐线 id。

第 3 条其实最符合「Override」这个命名，值得优先。

## 6. 结论

**线宽/颜色的值找到了，但用法还没找到。** 在链路打通之前不要接进 OCS 渲染——
拿一个样式套所有线，比继续用默认值更糟，因为它看起来像是对的。

## 7. 复现

```powershell
cargo run --example probe_geometry_style_link
```
