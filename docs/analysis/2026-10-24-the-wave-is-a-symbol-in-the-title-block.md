## 三、为什么上一轮读成「输入里没有」

三个环节叠在一起：

1. `decode_igsymbols` 的尺寸闸门是 `IGSYMBOL2D_MIN_PAYLOAD_LEN = 111`（文档写的是
   「113 / 121 两种」），这条是 **109**，整条被拒。其余校验都过：矩阵标签在 `+33`
   （搜索窗 64 字节内），六个数都是有限值且在坐标域内，尾部能读出两个 u32。
2. `probe_igr_remaining` 对两份模板各报一行
   `refused stream=/Sheet6 type=0x00ce class=Some("JSymbol") n=1` —— 只有一行摘要，
   没有位置，所以当时读不出它落在哪。
3. 家具渲染只画进得了模型的那几类实体（线 / 折线 / 弧 / 文本），被拒的记录连实体都进不了
   模型，「把 `.igr` 自己当图画一遍」自然没有这笔墨；而且它当时就算解出来也不会落墨 ——
   `push_entity_with` 那时没有 `SymbolInstance` 分支（第五节已补）。

另外，那三张「空着」的参考图不能当反证：`一级闪蒸分离器A`、`低温分离器A`、`换热器CD`
的参考 PDF 在标题栏窗口里**一条墨都没有**（`probe_body_against_reference --window 688 9 834 29`
的 “the reference inks:” 为空），不是「格子空着」而是整块标题栏没出。A 与低温A 的 `.pid`
里确有 `Linked` 的 `0x003D` 记录、CD 没有；我们用页幅认模板，所以这三张页面上多画了标题栏
（已知、被 `template-masks.json` 遮掉，本轮的残差口径不计）。

## 四、它是「签名」吗：是「比例」格里的一个自定义符号

`jsite_ref = 18` 指向模板里的 `/JSite18`，它的 `JProperties` 命名符号库
`C:\Users\ADMINI~1.WIN\AppData\Local\Temp\BLFH.sym`（UTF-16）；定义体缓存在 `/JSite16`，
`PSMcluster0` 2056 字节（无 `igLine2d`，两个 `JSheet`，3 条 `0x0081` 等）。

所以这不是设备库里的一件东西，而是做模板的人在临时目录里现做的一个小符号，名字缩写看着是
**比例符号**（`BL FH`）—— 与它被放在 `比例` 值格里完全一致。那条波浪就是这支符号的笔画，
不是手签，也不是出图时贴上去的图章：**同一条记录、同一份模板，两张图共用**。

局限：语料里没有 `BLFH.sym`（`Ref/Symbols` 下无此文件），所以这条记录的身份证据是位置
（0.02 mm）+ 唯一性（模板里只有这一条符号放置）+ 符号名。**闸门放开后这块局限也补上了**：
模板解析把 `/JSite16` 的 `JSheet 29`（A0）/ `JSheet 26`（A1）收进了 `symbol_definitions`，
各有 2 条可见图元；把它们按 placement 变换画出来就是参考图那笔波（见第五节）。

## 五、两段都落地了

1. **尺寸闸门改成「矩阵 + 尾部装得下」**。`IGSYMBOL2D_MIN_PAYLOAD_LEN` 不再是跟着 113 推出来
   的 111，而是最短可读记录：tag 最早的位置（4 字节 `JSite` id 之前）加上
   `IGSYMBOL2D_MATRIX_AND_TAIL_LEN = 72`（矩阵 32 + 插入点 16 + 缩放 8 + 标记字 4 +
   定义体两个 u32 8）。逐条再按 `matrix_at + 72` 校验 —— 本记录 `37 + 72 = 109` 正压在线上，
   108 字节被拒。两个单测钉住两端：
   `igsymbol2d_decodes_the_109_byte_title_block_placement` /
   `igsymbol2d_rejects_a_payload_one_byte_short_of_the_matrix_and_tail`。
2. **家具通道会画符号放置了**。`lay_out_drawing` 里那段 `SymbolInstance` 展开拓成
   `push_symbol_instance`，模板的家具循环照它走：先取 placement 的 `definition`（缓存体），
   再回落到 `.sym`。模板解析把 `/JSite16` 的 `JSheet 29`（A0）/ `JSheet 26`（A1）收进了
   `symbol_definitions`，各有 **2 条**可见图元 —— `BLFH.sym` 不在语料里也没关系。
   模板自己的 `.sym` 缺失记在一份独立的账上，不掺进图纸的 missing-symbols 报告，也不会在
   标题栏里画缺符号方框。

落墨结果（`--window 1070 14 1118 24`，A1 那份整体左移 348.00 mm）：

```text
the page draws:
  arc      (1098.39,  19.41)->(1100.69,  19.00)  decoded   furniture [Temp/BLFH.sym]
  arc      (1100.69,  19.00)->(1103.01,  18.56)  decoded   furniture [Temp/BLFH.sym]
```

参考侧 9 段离这两条弧 **0.00–0.11 mm**（此前 2.46–2.99 mm，且页面那格是空的）。

先把口径钉死：参考 PDF 的 16 条流里**一条曲线算子也没有**（`c` / `v` / `y` 各 0 条，`l` 11299 条），
所以那 9 段是**打印驱动**自己折线化的结果；其中顶点落在被折的那条曲线上，折线化只会把弦的内部
挖进去。逐点量下来（`probe_arc_against_reference`）：

| 位置 | 量到的 | 说明 |
|---|---:|---|
| 弦端点（顶点） | 径向 +0.061 / +0.065（第一瓣）、−0.087 / −0.094（第二瓣）；最坏一个离我们 0.112 mm | 顶点在曲线上，折线化不移动它 —— 这是印出的曲线与我们两条弧的形状差 |
| 弦内部，第一瓣 3 支 | 0.027 / 0.036 / 0.044 mm | 与 r = 1.45 mm、0.68 mm 弦的弦高 0.040 mm 同量级：这一层是驱动折掉的 |
| 弦内部，第二瓣 3 支 | 0.096 / 0.098 / 0.097 mm | 0.09 的形状差 + 弦高 |

那个最大的 0.112 mm 落在第一瓣的起点：印出的曲线比我们的弧多走 **3.7°（0.093 mm）**、径向外
**0.061 mm**，合起来 0.112 —— 没有一分来自折线化。也没有一分来自解码：缓存体记的就是
`r = 1450 µm`、圆心 `±(1000, 1050) µm`、起止角 `3.597093390 / 5.473401735 rad`，我们的纸面弧
正是这串数（1.45 mm、相对插入点偏移 1.0 / 1.05 mm、−153.90° → −46.40°），一位不差。

顺着这条再看印出来的波本身：按最近弧把折点分组做最小二乘圆，第一瓣 5 点落在
r = **1.5000** mm（rms 8.7 µm），第二瓣 5 点落在 r = 1.5087 mm 但 rms **39.9 µm**、残差正负交替
—— 两瓣的半径并不矛盾（相差 8.7 µm，在落格误差内），矛盾的是**第二瓣根本不是圆**。冷眼一看
像「同一对弧放大 1.034 倍」：那会把第一瓣圆心送到 (1099.6584, 20.0858)，离拟合值 4 µm。但
同一比例会把第二瓣峰顶抬到 19.414，而印出的是 19.304；更要紧的是缓存那对弧的 y 只够到
0.800 mm，印出的墨是 **1.016 mm**，而 x 只长 2.6% —— 相似变换没法同时给出 2.6% 和 27%。
所以打印用的不是这份缓存体；第七节把这件事做到底。

整页 `--residual`：**7.1 / 0 / 7.1 / 0 / 0 → 0.0 / 0 / 0 / 0 / 0 mm**（`I井场` 只剩一个长度
0.0 的单采样段），五张合计 **45.8 → 0.0 mm**。

## 六、限制

- 参考 PDF 是 Amyuni PDF Converter 4.5.2.9 的「打印成 PDF」产物（2026-10-12 11:53 / 11:59），
  单内容流、无 `/Annots`、无 `/OCProperties` —— 这一条排除了「PDF 层贴的注解」，但本文的
  结论不依赖它：记录在 `.igr` 里，位置对得上。
- 只验了两份模板各一条；`test-file/Ref/Template Files` 里的同名副本与语料那两份是否逐字节
  相同没查。
- 「比例符号」是从 DOS 短名反推的读法，`BLFH` 也可能是别的东西；确定它是什么要打开那个
  `.sym`。
- **缓存体与印出的波浪差 0.05–0.11 mm**（第七节定量）：打印走的是记录里那个 `.sym`，不是模板
  缓存的这份体 —— 缓存的第一瓣半径小 50 µm、第二瓣是弧而印出的不是、两端各短 0.10 mm。
  0.11 mm 不到一支笔宽（0.169 mm）的七成、也远在 0.5 mm 比较窗口内，整页残差仍是 0；再往下
  对需要那份 `BLFH.sym`。

## 七、那 0.09 mm 归谁：打印走的是库体，不是缓存体

第五节的 0.112 mm 拆到最后只剩两个候选：我们的弧读错了，或者打印用的不是这份缓存。这一节
把第二个候选坐实，三条证据互相独立。

**先钉测量下限。** 参考页 **11 291 段的每一个端点都落在 1/600 英寸的格点上**（最大偏离
0.0008 px；笔宽也全是 1/600 in 的整数倍：0.169 / 0.339 / 0.677 mm = 1 / 2 / 4 px）。所以每个
印出的顶点每轴最多带 **±0.021 mm** 的落格误差，小于这个数的形状差别不是测量。两页印的是
同一条路径（A1 的十个顶点与 A0 逐点差 347.980 mm，y 一位不差），所以这不是两份独立样本。

**缓存侧只有一份体。** 两份模板的 `/JSite16` 里 `JSheet 29` / `JSheet 26` 是唯一非空的本体
（`probe_template_body_curve`）：两条弧、`r = 1450 µm`、圆心 `∓(1000, 1050) µm`、起止角
`3.597093 / 5.473402` 与 `2.331809 / 0.431956 rad`，在插入点 (1100.6925, 19.0000) 相切
（切线 43.61°）。同一存储里 `circles 0 / arcs 2 / lines 0 / polylines 0 / texts 0 /
bsplines 0 / ellipses 0 / boundaries 0`，另一张 `JSheet 6` 是空体 —— 「换一份缓存」在这份文件
里没有别的候选。

**把十个顶点按最近弧分组，做几何最小二乘圆。** 第五节那两个数（1.4994 / 1.4716）是 Kåsa 代数
拟合，散开的一瓣会被读成偏小的半径；换成 Gauss–Newton 迭代到 `|p − c| − r` 之后：

| 瓣 | 点 | 拟合 | rms | 判读 |
|---|---:|---|---:|---|
| 第一瓣 | 5 | 圆心 (1099.6580, 20.0821) r **1.5000 ± 0.0040** | **8.7 µm** | 就是一条弧，比缓存的 1.45 大 50 µm |
| 第二瓣 | 5 | 圆心 (1101.6314, 17.8528) r 1.5087 ± 0.0179 | **39.9 µm**（残差 +13 / −41 / +56 / −50 / +22 µm） | **没有哪个圆是** |

第一瓣的每个四点子集都拟合到 ≤ 9.3 µm；第二瓣删掉任一点后的四点子集最差 40.5 µm、最好
17.1 µm，而后者给出 r = 1.8008、与其余子集的 1.20–1.54 不连号 —— 不是「某个顶点是噪点」，
是这一瓣没有圆的形状。把整条波当**一对在自由交点相切、两个半径都自由**的弧再拟一遍
（5 个参数，`probe_arc_against_reference` 新增那段）：交点 (1100.6625, 18.9747)、切线 42.51°、
r1 1.4927、r2 1.4685，**rms 29.2 µm** —— 仍比落格误差大两倍多。

**第三条证据不用拟合。** 缓存那对弧的 y 只够到 18.600–19.400（0.800 mm），印出的墨是
18.457–19.473（**1.016 mm**），而 x 只从 4.619 长到 4.741（+2.6%）。相似变换同时缩放两个
方向，2.6% 与 27% 不可能同源；两端的顶点还各自比缓存的弧多走 **0.112 / 0.104 mm**。

结论：**打印走的是记录里那个 `.sym`（`…\Temp\BLFH.sym`），不是模板缓存的这份体。** 缓存比
印出的符号短一截（两端各 0.10 mm）、小一圈（第一瓣 −50 µm 半径）、第二瓣干脆不是弧。语料里
没有 `BLFH.sym`，所以这两份是「先后两版」还是「同一版的两种序列化」，这里判不了；能判的是
它们不是同一份几何。顺带一条：`push_symbol_instance` 缓存优先，所以就算把那份 `.sym` 补进
语料，这一页仍会画缓存那对 1.45 的弧 —— 0.09 mm 不会自己消失。

### 顶点能反推到的，和推不到的

- **推得到**：第一瓣是一条圆弧 —— 半径 1.5000 ± 0.0040 mm、圆心 (1099.6580, 20.0821)，扫过
  −155.91° → −47.92°。它比缓存的弧大 3.4%、圆心朝外挪 0.047 mm，但形状就是圆（rms 8.7 µm，
  落在落格误差的量级）。
- **推得到（否定式）**：第二瓣不是圆弧。没有半径能解释它（五点 39.9 µm；四点最好 17.1 µm 但
  半径不连号），两瓣合成一对相切弧也不行（29.2 µm）。它的峰顶是一段平台（两个顶点同在
  y = 19.304），平台法线落在 94.4° 而不是圆的 90° —— 等角折线的弧不会有这个偏。
- **推不到**：控制点。第二瓣只有 5 个顶点、落格噪声 ±0.021 mm，而折线化不是等角步长
  （第一瓣 23.4 / 29.1 / 26.2 / 29.3°，第二瓣 26.1 / 26.4 / 23.0 / 8.8°），说明驱动是按弦高
  **自适应**折的：顶点数（每瓣 4 支）是驱动的，不是源曲线的性质；末支那 0.239 mm 也不是结点，
  只是容差走完了。这种采样下一条三次 Bézier / B 样条总能在噪声内拟合成功，所以「拟合上了」
  不能证明它是样条。**「第二瓣是样条」与证据相容**（曲率沿瓣在变、平台法线偏 3.6°），
  **但没被证据证明**；要定案只能打开 `BLFH.sym`。

## 八、缺源账：模板家具的符号，谁只有缓存、谁连缓存都没有

第七节的结论是「打印走的是语料里没有的那份 `.sym`」。把它记成一条账，才不至于下一轮把它再读
成解码错。`PaperModel.template` 现在带 `symbols: Vec<TemplateSymbol>` —— 每个家具符号放置一行，
记它叫什么、插入点、`body: Library | Cached | Missing`、以及 `library_available`（那个 `.sym`
在库共享里能不能真的读到）。`probe_body_against_reference --residual` 先走遍备份里的全部图纸，
把这份账打在最前面：

```text
template furniture symbols, over 53 sheets laid out
symbol               count  sheets  body
BLFH.SYM                31      31  cache only — no share in the path, and no .sym of that name
  (0 placements read their .sym from the library)
```

- **只有缓存体：1 个符号 / 31 个放置 / 31 张图。** 53 张图里只有 31 张挂了模板（余下的没有家具：
  A2 图纸不匹配 A0/A1 模板的纸张范围，16 张属这一类），这 31 张的模板各放一次 `BLFH.sym`，
  无一例外。
- **连缓存也没有：0 个。** `Missing` 这一类今天是空的 —— 每一处放置都有 `JSheet 29`/`JSheet 26`
  那份缓存兜着，所以 14.2 mm 能落墨。
- **从 `.sym` 读的：0 个。**
- **这一类为什么结构性，以及那条结构现在有了出口。** 记录里那条路径是
  `C:\Users\ADMINI~1.WIN\AppData\Local\Temp\BLFH.sym`：作者机上的临时目录，路径里没有
  `…\Ref\Symbols\` 这一段，`library_relative_path` 直接返回 `None`，所以共享里摆在哪都不按路径读到它。
  库现在多了一条**按文件名**的回落：路径不进共享时，取文件名的 `.sym`，由**第一个恰好只有一份**该名
  文件的根供给（同一根里两处同名则拒收 —— 两个不同符号可以共用一个文件名，猜错比不画更糟）。
  于是今天这条账只说明**语料确实没有这个文件**，而不是「有也读不到」：拿一个只放一份 `Temp/BLFH.sym`
  的根（`PID_SYMBOL_LIBRARY` 指过去）重跑，同一 31 行立刻从 `library_available == false` 翻成 `true`，
  账面写成 `cache only — the .sym is in the library too, and the cache still wins`。**注意：页面仍然
  画缓存体** —— `push_symbol_instance` 先试缓存是既定顺序，本轮只补了「库体读得到」这件事。
  语料里没有这份文件，所以 `0` 这个数不变。
- **两种「没有」不是一回事：文件不在库里，还是库里同名两份、我们拒收。** 按名回落只能取
  **唯一**的一份，同一根里两处同名就拒收 —— 于是缺源账多了 `TemplateSymbol.name_gap:
  Option<NameMiss>`（`NoSuchFile` / `NotUnique`）。实测两条：

  ```text
  # 一根只放一份 Temp/BLFH.sym
  BLFH.SYM   31   31  cache only — the .sym is in the library too, and the cache still wins
  # 一根的两处各放一份 BLFH.sym
  BLFH.SYM   31   31  cache only — the library carries that name twice, so it is refused
  ```

  第二条**不是缺源** —— 文件在语料里，是我们自己决定不挑。把它数成「缺文件」会让下一轮去找一份
  已经在手上的东西。
- **账的用法。** `--residual` 的每一段残差现在带一个 `template_source`（体、key、以及 `name_gap`）：
  落在家具放置的墨迹框内、且那个放置不是从 `.sym` 读的，就在行尾注
  `<- no <key> in the library` / `<- no <key> of that name in the library` /
  `<- <key> refused: the library carries that name twice` / `<- nothing draws <key>`，并单列一节
  `missing sources: X mm in N runs`，不掺进「按最近页图元签名」那张解码计分表。今天这一节是
  **0.0 mm / 0 段**（五张有参考图的图整页残差已是 0.0 / 0 / 0 / 0 / 0），账是空的，但口径立住了：
  **这一类墨迹被归到「缺源」，不会归到「解码错」。**
- **门禁。** `pid-plot/tests/border_template.rs` 的 A1 用例钉住这份账：模板恰好一个符号放置、
  文件名是 `BLFH.sym`、`body == Cached`、`library_available == false`、`name_gap == NoSuchFile`（不是
  被拒收）、`extent_mm` 有值、插入点归它自己、且**不**出现在 `missing_symbols` 里。
  A0 那页（`I井场`，`CPE-SQ-A0.igr`）另有一条同样的用例：模板 174 实体（那条符号展开成缓存体的
  两条弧）= **175** 条家具图元（34 条文字）、外框 `(0,0)–(1189,841)`、内框 `(25,10)–(1179,831)`，
  同一个符号放在 `(1100.692, 19.000)`，两条弧 `(1098.39, 19.41) → (1100.69, 19.00) → (1103.01, 18.56)`
  —— 比 A1 的 `752.692` 正好多 **348.000 mm**，即两页页宽之差（1189 − 841）。两页此前只有 A1
  一页被看着。
- **两页的字号是同一套（A0 也量了）。** A0 用例同样 `write_plot` + `read_plot`，并读 `I井场` 自己那份
  参考 PDF：`审  定` 11.17 / 4.74、`设计证书号` 20.08 / 5.08、`1 版` 6.78 / 4.40、
  `华北油田苏桥储气库群` 45.33 / 5.93、`中国石油…华北分公司` 107.46 / 6.60（宽 / 字高，mm）——
  **与 A1 参考量出的五个数一位不差**（±0.02），所以不是两页各有一套字号；我们的页面每个字组
  落在参考宽度的 2.5 % + 0.05 mm 以内、字高 ±0.05 mm。两页标题栏的 span 逐条相差 `348.00 mm`

  `pid-plot/tests/template_symbol_gap.rs` 把三种情形走一遍真实布局：空根 → `NoSuchFile`；两份同名 →
  `NotUnique`；只剩一份 → 不再是 gap、`library_available == true`（页面仍画缓存）。
  `pid-plot/tests/export_plant_backup.rs` 把这份账按到全包：每张有模板的图纸恰一个家具符号、
  体一律来自缓存、`library_available == name_gap.is_none()` 必须成立、模板自己的缺口不得串到图纸的
