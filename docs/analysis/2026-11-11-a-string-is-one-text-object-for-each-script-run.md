# 一个字串按文字种类写成几个文字对象：参考图从不把汉字和拉丁字母写在一起

日期：2026-11-11　`main`：`abced22` 之上

## 结论

出图程序把一条标签的字串一次交给 GDI，带着每个字的整像素步进。到了 PDF 里它不是一个文字对象：字串在文字
种类变化的地方被切开，每一段是一个文字对象，有自己的起点和自己的字距。11 张参考图的 6416 个文字对象里，
没有一个同时含汉字和拉丁字母，也没有一个把全角括号和这两类写在一起；同样这些标签，我方原先写成一串，
这样的文字对象有 197 个。

写出器现在照参考图切（`pid-plot/src/write/script_runs.rs`）。这一步不动任何门禁读数：字串的第一个字和
最后一个字都在原处，只有中间的字挪到参考图上它们所在的位置，最远 0.31 mm。它是下一步的前提——驱动把
压窄的字体写成 256 分之几之后，字会一点点偏离步进，偏离只在一个文字对象内部累计，所以文字对象在哪里
断开决定了一条长标签的总宽。

## 参考图上的证据

`D:\work\cad\pid-test-data\验收数据` 的 11 份参考图，逐个文字对象看它含哪几类字符：

| 一个文字对象里的字符 | 个数 |
|---|---:|
| 只有拉丁字母一类（可带数字、空格、标点、符号） | 3477 |
| 只有汉字一类（可带数字、空格、标点、符号） | 776 |
| 只有全角括号一类（可带数字、空格） | 34 |
| 三类都没有（纯数字、标点、空格、`℃`） | 2129 |
| 汉字与拉丁字母同在，或任一类与全角括号同在 | **0** |

参考图把这些标签写成几个文字对象（`|` 是切口）：

| 标签 | 参考图的文字对象 |
|---|---|
| `DWG-0100集05-37` | `DWG-0100` \| `集05-37` |
| `苏49K-P5注采井` | `苏49` \| `K-P5` \| `注采井` |
| `G井场来` | `G` \| `井场来` |
| `采气生产管线去G井场` | `采气生产管线去` \| `G` \| `井场` |
| `I井场（2口井）` | `I` \| `井场` \| `（2` \| `口井` \| `）` |
| `CADD号` | `CADD` \| `号` |
| `天然气自压缩机X-01141出口来` | `天然气自压缩机` \| `X-01141` \| `出口来` |
| `工程设计证书: A111017147 综甲     工程勘察证书: B111017147 综甲` | `工程设计证书: ` \| `A111017147 ` \| `综甲     工程勘察证书: ` \| `B111017147 ` \| `综甲` |

这些标签各是一个文字对象：`苏49-2老井`、`1 版`、`i≥3‰`、`SP:30℃`、`25-CI-1001901-B2-EH40`、`H=11.8MPa`。

规则由此读出：

- 三类字符各自开一段：拉丁字母、汉字、全角字符（见证到的只有 `（` 和 `）`）。遇到与当前这一段不同的一类，
  就从它切开。
- 其余字符——数字、空格、ASCII 标点、`≥`、`‰`、`℃`——留在它前面那一段里；字串开头的这类字符归第一段
  （`1 版` 是一个对象）。

## 每一段从哪里起笔，字距怎么定

A2 图（`轻烃分离器I`）标题栏的证书行是 5 个文字对象，它把这两件事定下来：

| 段 | 起点（设备单位，自标签起点） | `Tc` |
|---|---:|---:|
| `工程设计证书: ` | 0 | −0.494 |
| `A111017147 ` | 134 | −0.288 |
| `综甲     工程勘察证书: ` | 238 | −0.453 |
| `B111017147 ` | 457 | −0.288 |
| `综甲` | 561 | −0.576 |

- **起点**是它前面所有字的整像素步进之和。步进是出图程序对整串算的：取整的误差跨过切口往后带，不在每一段
  重新开始。第二段的 11 个半角字因此是 9、10、9、10……共 104，而不是从 10 起。
- **字距**是这一段自己的字需要的平均值：第一段 7 个间隙共少 6 个单位，第二段 10 个间隙共少 5 个单位。

写出器的整像素步进模型（`run_advance` 的 `pixel_steps`）对这一行给出的正是 0、134、238、457、561，每段的
字距 −0.4937、−0.2880、−0.4526、−0.2880、−0.5760。第三段比参考图小 0.0004，因为参考图的 `Tc` 是在它自己
写的矩阵 213/256 之下说的，我方这一步还在 0.8333 之下说；矩阵另文处理。

## 写出器的改法

- `write/script_runs.rs`：`of` 把字串切成段；`start_px` 给一段的起点；`spacing_pt` 给一段的字距。
- `write.rs` 的 `show_text`：正排的字串按 `of` 切开，第一段照旧起笔，后面每一段用 `Td` 放到
  「字串第一个字的位置 + 前面各字的步进」。每一段内部照旧：除最后一个字外都在自己的 `Tc` 下，最后一个字
  单独写、不带 `Tc`。
- 旋转的字串不切：它的每个字本来就各自落在自己的步进上。借字样本覆盖的那一类标签（`write/borrowed.rs`）
  不切。记录分段的规则（`SP:`）照旧，在它之内再按文字种类切。

## 读数

两道门禁（`reference_plots_acceptance`、`reference_plots_ink`）在这一步之后：

- 验收门禁通过，钉值一个没动：超限标签仍是 47 条。
- 墨迹门禁通过，它写出的读数表 211 行逐行相同——每页的覆盖率、未覆盖、多余墨、配对的标签数、笔宽一致数
  都在这张表里，所以这些读数也都没变。

我方 11 张验收图上把两类以上写在一起的文字对象 197 → 0（汉字与拉丁字母同在 180、汉字与全角括号同在 8、
三类同在 9）；文字对象总数 8019 → 8338。参考图是 6416 个，它把旋转的字逐个写成对象，我方把正排的每一段
拆成「带字距的前几个字」和「最后一个字」两个对象，所以两边的总数本来就不同。

把 83 张图（验收 11、共享 5、备份 53、夹具 7 按两种语料各一遍）改前改后各导出三遍（成批、单张、
`pid_plot`），逐页比：

| 语料 | 有变化的页 | 移位的字形 | 最远 |
|---|---:|---:|---:|
| 验收 11 | 11 | 2240 / 28942 | 0.250 mm |
| 共享 5 | 5 | 1005 / 9515 | 0.138 mm |
| 备份 53 | 53 | 9087 / 112189 | 0.250 mm |
| 夹具 7（自带语料） | 7 | 479 | 0.306 mm |
| 夹具 7（共享语料） | 6 | 339 | 0.250 mm |

笔画一条没变（几何、次序、颜色、线宽都相同）；没有字形换字型、字号或颜色，没有字形多出来或少掉。三种导法
的变化相同；单张导出与 `pid_plot` 的输出 83 页逐字节相同。

移位的都是混排标签中间的字。以证书行为例，改后 5 段的起点与参考图逐个相同（相距 134、238、457、561 个
单位），改前只有第一个字和最后一个字对得上。

## 没有见证的

- CJK 标点块的字符（`、`、`。`、U+3000）：留在前一段里。
- `（`、`）` 以外的全角字符：与它们同类。
- 假名、谚文、希腊字母、西里尔字母：留在前一段里。
- 一个字型画不了、要借别的字型画的字符：照旧按字型切，不在本文范围内。

## 复现

```powershell
# 一批 PDF 的文字对象各含哪几类字符（读内容流，不经过任何「拼词」）；加 --cuts 列出切口
python -X utf8 tools/pdf_text_objects.py scripts <参考图或我方导出的 pdf> ...
# 一个点附近的文字对象：起点、`Tc`、与前一个对象的间隙（证书行在 A2 图的 (500, 88) mm 附近）
python -X utf8 tools/pdf_text_objects.py near <pdf> 500 88 70
# 规则与证书行的起点、字距
cargo test -p pid-plot --lib script_runs
# 写出的页面上一条混排标签是几个文字对象、各自的 Td 与 Tc
cargo test -p pid-plot --lib a_string_that_changes_script
```
