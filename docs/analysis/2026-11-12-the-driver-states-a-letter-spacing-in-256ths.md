# 字距 `Tc` 是驱动拿 256 分之一个设备单位算出来、截断到三位的

2026-11-12，排字第八批。规则是第六次独立审查（固定在 `9e045e1`）从 11 张参考图里搜出来的；这一篇记它怎么写进
写出器、读回来对上多少、哪些地方没有见证。代码在 `pid-plot/src/write/letter_spacing.rs`。

## 1. 规则

出图程序把一个字串连同每个字的整设备单位步进交给 GDI（`run_advance` / `pixel_steps`）。字在字体里自己的
前进量不是整单位，PDF 驱动把字串写成一个文字对象，用字距 `Tc` 把差额摊到每个字后面：

```text
前进量 = round(字在设备字体里的前进量 × 256) / 256            就近取到 1/256 个设备单位
Tc     = 截断到三位((S − 前 n−1 个字的前进量之和) × 0.48 / ((n−1) × m))
```

- `n`：这个文字对象的字数；求和只到倒数第二个字。
- `S`：首字原点到末字原点的整设备单位数，也就是前 n−1 个字的步进之和。设备单位是 1/150 英寸，0.48 pt。
- `m`：文字矩阵沿基线那一项，取驱动留着的 256 分之几（`0.797` 是 204/256）；不压窄、不旋转时是 1。见
  `2026-11-11-the-driver-states-a-font-transform-in-256ths.md`。
- 截断是向零截断；末尾的 0 不印（`0.08`、`-0.21`），零印成 `0`。

与文字矩阵是同一套定点数：1/256。前进量是**就近**取，商是**截断**。

写法上，参考图是 n 个字一个文字对象、都在这个 `Tc` 下：`Tc` 也跟在最后一个字后面，但驱动给每个文字对象各写
一个 `Tm`，那一点多出来的位移不落在任何字上。

## 2. 依据

审查的读数（它的报告第 6 节，脚本与日志在审查目录里，不在仓库）：

- 参考图里多于一个字的文字对象 3 986 个，全部正排（旋转的标签一个字一个对象，不带 `Tc`），五种字型十七档
  （不压窄九档、压窄的宋体八档），规则逐个印出参考图的 `Tc`。
- 排除掉的写法（不压窄的 3 805 个对象上的命中数）：前进量不取整 2 434；取到 1/512 是 2 894、1/1024 是 2 545；
  商四舍五入或向下取整都不到 2 900。
- 手头 5.5.2.7 版驱动（出参考图的是 4.5.2.9）写文字的那个函数是同一个结构：字的前进量是 1/256 个设备单位的
  整数，步进是整设备单位，逐个间隔累加，除以「间隔数 × 矩阵的 256 分之几」。反编译文本里看不到的两处——
  前进量取整的方向、数字怎么印——只有参考图作依据。

## 4. `S` 是步进，不是画出来的位置

审查用我方导出的首末字距离取整当 `S` 时，有 9 个对象对不上，全在标题栏两档压窄的宋体上：`Tf 18.72` 的公司名
（21 个字，7 张图）与 A2 `Tf 32.16` 的两行（12 个字、5 个字）。它们的步进之和是 604、575、209，规则印出
`0.124`、`0.169`、`0.155`，与参考图相同；写出器本来就是这样排步进的，现在这 9 个也相同。

对不上的原因在量法：这两档字的矩阵压得多（`0.77`、`0.773`，是 197/256、198/256 印成三位），`Tc` 又被截断，
PDF 里画出来的末字离步进 0.58～2.3 个设备单位——参考图自己就是这样（604.578、572.695），我方画在同一个位置。
拿画出来的位置取整得到的是 605、573、208，不是 `S`。所以 `S` 永远取出图程序的步进，不从页面上量。

## 6. 没有见证的

- **后面有一段接着起笔的字串**：驱动会给每种字体各写一个文字对象、各在整设备单位上起笔；写出器里后一段接在
  前一段的笔位上，所以前一段仍把最后一个字单写，使笔位停在那个字的末尾，位置同以前。同一种样式的记录的
  后一段在没有设备网格的页面上也是这样接着写的（71 页上没有这样的标签）。参考图上没有这种标签
  （以 `℃` 结尾的那一类是逐字写的，另有规则）。
- **前进量恰好在两个 256 分之一正中间**：取远离零的一侧，与审查的搜索脚本相同。参考图分辨不了这一点：
  五种字型的字格是 256（宋体、新宋体、仿宋）、2288（Arial）、2319（Arial Narrow）个设计单位，含 2 的幂次都
  不到 512，前进量乘 256 算不出恰好一半。用 Inter（字格 2048）的 `A` 做替身的库内用例里出现过一次：`A` 宽
  1413 个设计单位，在 `Tf 9.6` 下是 3532.5 个 256 分之一，借来的 `动火点` 那条用例因此只能把步进断言到
  「9 个单位 ± (1/512 个单位 + 0.001 pt)」，也分不出正中间往哪边倒。2026-11-12 把那条用例的替身换成 Inter 的
  破折号（整 2048 个单位，与新宋体的汉字一样是整 em、20 个设备单位）：`Tc -5.28` 逐位相等，步进恰好 9。正中间
  取哪一侧现在只由 `letter_spacing.rs` 里明文的 `2470.5 → 2471` 钉着，仍然没有见证。
- **旋转的字串带 `Tc`**：参考图上旋转的字都是一个字一个对象；写出器对旋转的字逐字落步进，不走这条规则。两张
  夹具上恰好 180° 的那条标签按正排写成字串加 `Tc`，没有参考图。
- 出参考图的 4.5.2.9 版驱动没有读到。

## 7. 用例

- `letter_spacing.rs` 5 条：标题栏三档的 `0.124` / `0.169` / `0.155`；A2 证书行的 `-0.494` / `-0.288`；就近取
  与截断各一例（2470.2 → `0.168`，2470.5 → `0.166`，负数 `-0.166`）；除以矩阵那一项（`0.48` 对 `0.602`）；
  没有间隔、截成零、矩阵不是数时是 0。
- `write.rs`：`a_string_is_one_text_object_under_the_drivers_letter_spacing`（改前
  `Tc -0.08949152542372815 is not the driver's -0.089`）、
  `a_stated_width_is_set_under_the_matrix_the_driver_writes`（逐位相等）、
  `a_string_another_piece_carries_on_from_has_its_last_glyph_apart`、
  `a_record_run_with_no_start_of_its_own_carries_on_from_the_glyph_before_it`。
- 验收门禁读不到这条规则：它读位置，新旧两种写法的字最多差 0.008 mm。
