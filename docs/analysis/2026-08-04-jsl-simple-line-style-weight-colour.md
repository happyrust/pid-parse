# 线宽与颜色找到了：`0x002E` payload `+34` / `+50`

> 日期：2026-08-04
> 范围：`pid-parse`
> 结论类型：**字段已定位**（值域自证 + 两图交叉）；尚未做 native-reader 复核与 promotion。
> 前置：`2026-08-04-stylecluster-record-chain.md`、`2026-08-04-jsl-text-char-style-height.md`
> 工具：`examples/probe_jsl_line_style`

## 1. 布局

`0x002E`（**JSL Simple Line Style**，style.dll）payload：

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+14` | `u32` | **样式 id**，每条记录唯一（与 `0x002C` 同偏移、同语义） |
| `+34` | `f64` | **线宽，单位米** |
| `+50` | `u32` | **颜色**，字节序 `[R, G, B, 0]`（即 Win32 `COLORREF` / `0x00BBGGRR`） |

payload 有 54 / 58 两种长度，**三个字段在两种长度上都成立**。

## 2. 为什么确定 `+34` 是线宽

ISO 128 规定的线宽系列是 `0.13 / 0.18 / 0.25 / 0.35 / 0.5 / 0.7 / 1.0 / 1.4 / 2.0` mm。
实测取值：

| 流 | 读出（mm） | 落在 ISO 档上 |
|---|---|---|
| DWG-0201 `/StyleCluster` | 0.100, 0.180, 0.350, 0.700, 1.000 | 4/5 |
| DWG-0201 `/JSite329` | 0.130, 0.350, 0.500, 2.000 | **4/4** |
| 工艺 `/StyleCluster` | 0.100, 0.130, 0.350, 0.700, 1.000 | 4/5 |
| 工艺 `/JSite7559` | 0.130, 0.350, 0.500, 2.000 | **4/4** |

除 `0.100`（细线常用值，不在 ISO 系列内）外全部落在 ISO 128 档位上。
**两张无关图纸给出同一组档位**，这是线宽才有的取值分布。

## 3. 为什么确定 `+50` 是颜色

按 `[R, G, B, 0]` 解出来的取值：

| 流 | 颜色 |
|---|---|
| DWG-0201 `/StyleCluster` | `#000000` `#800000` `#008000` `#808000` `#FE0060` `#FFA777` `#0000FF` |
| 工艺 `/StyleCluster` | `#000000` `#800000` `#FF0000` `#008000` `#808000` `#0000FF` |
| 工艺 `/JSite7559`（58 字节档） | `#000000` `#FF0000` `#008000` `#0000FF` |

黑 / 深红 / 红 / 深绿 / 橄榄 / 蓝——**标准 CAD 调色板**。两张图独立给出同一组基色，
且 `#800000`、`#808000`、`#0000FF` 这种 VGA 16 色的取值不会由噪声产生。

字节序判据：`#0000FF` 解为 R=0 G=0 B=0xFF（蓝），`#800000` 解为 R=0x80（深红）。
若字节序取反则会得到「蓝=红、深红=深蓝」这种不合理配色，所以 `[R, G, B, 0]` 是对的。

## 4. 与 `0x002C` 的一致性

`+14` 在文本样式与线样式上是**同一个偏移、同一个语义**（每条记录唯一的样式 id），
说明 JSL 样式记录有一个共同的头部布局。这为后续解其余样式族
（`0x002A` Simple Fill、`0x002B` Hatch Fill、`0x002D` Text Paragraph、
`0x002F` Simple Dash Type）提供了现成的起点。

## 5. 还没做的

1. **端到端 join 未验证。** 与字高同一个问题：还没证「某条 `igLine2d` → 取到它的
   线样式 id → 拿到线宽颜色 → 画出来是对的」。而且 `igLine2d` 记录本身**没有**
   样式 id 字段（50 字节字节全额入账），所以这条链的中间环节是什么还不知道
   ——很可能要经过 `0x00FA` Dependency Object。
2. **native-reader 复核未做**，同 `0x002C`。
3. 少数记录 `+34` 落在范围外（16 条里 2 条、6 条里 1 条），未解释。

**在第 1 项做完之前不要接进 OCS 渲染**——知道颜色值在哪，不等于知道哪条线用哪个颜色。
