# 五张语料里没有 U1 的显示比例

> 日期：2026-10-11
> 范围：只读（计划 `OpenCADStudio/docs/plans/2026-10-11-dash-pitch-follows-a-view-scale.md` U3；协同任务 t-193）
> 对照：U1 周期法 **s = 1.67 ± 0.03**（`OpenCADStudio/docs/evidence/2026-10-11-dash-pitch-reference-measurements/README.md`）。5/3 = 1.666667、160/96 = 1.666667 都在这带里。旁边两带只作排除：1.75 ± 0.02（英制图案，U1 已排除）、线宽 1.80 ± 0.08。
> 换算就这四种：原值、1/原值、×25.4、÷25.4。
> 工具：`examples/probe_dash_scale_field_candidates.rs`

**命中字段：无。0x002F 与 0x002E 的单位码相同，都是 11。**

五张图（0201、0202、D06、工艺管道-1、A01）里，没有一个字段在各图取同一个数，并且这个数或上面四种换算落在 1.67 ± 0.03。下面每个候选都给了五图的值。落进带里的两个数（页宽的倒数、f32 高半字 1.875）身份都不是比例，写在各节里。

## 1. JSheet 小浮点

`0x0114` 条数：0201 二十二、0202 十三、D06 十、工艺管道-1 十一、A01 八。

T2 在 0201 模板 sheet 上见过的那一对，本轮仍只有一条：

| 图 | payload +184 / +188 的 f32 0.5 / 0.03125 |
|---|---|
| 0201 | **有，1 条**：oid **501**，类型字 `0x0114`，`bytes_to_follow` 358。字节在文件偏移 `0x1602D`：`00 00 00 3F 00 00 00 3D` |
| 0202 | 无 |
| D06 | 无 |
| 工艺管道-1 | 无 |
| A01 | 无。另有一条够长的记录 +184 = 0.00010109、+188 = 0.05054418，不是这对 |

实例 sheet **119**（`/JSite396/PSMcluster0`，232 字节）没有这对数。它在 (10⁻⁵, 20) 且不是 1 的对齐 f32 只有 +16 的 1.875，也就是下面那个 1.0 的高半字。

501 的换算（都不在 1.67 ± 0.03，也不在 1.75 ± 0.02、1.80 ± 0.08）：

| 原值 | 1/原值 | ×25.4 | ÷25.4 |
|---:|---:|---:|---:|
| 0.5 | 2 | 12.7 | 0.019685 |
| 0.03125 | 32 | 0.79375 | 0.001230 |

同一条 501 的 payload **+12 是 f64 1.0**（字节 `00 00 00 00 00 00 F0 3F`）。把 +16 读成 f32 得到 **1.875**（`0x3FF00000`，1.0 这个 double 的高半字）。0201 有 20/22 条 JSheet 在 +16 出现这个 1.875，是这个别名，不是第二个比例。探针把「对齐 f32」扫进 1.80 ± 0.08 的那一批 1.875，都是它。

其余 JSheet 对齐 f32（1.36、1.59、1.64 一类）在同一张图的不同 sheet、不同偏移上散开，没有五图共用的一个数。其中 1.64433789 距 1.67 有 0.026，卡在 ±0.03 的边上，但只是若干 sheet 上重复出现的结构槽，不是图纸级比例。

## 2. 视图：ViewFilterSet / SheetView

| 记录 | 0201 | 0202 | D06 | 工艺管道-1 | A01 |
|---|---:|---:|---:|---:|---:|
| `0x0057` 显示态（布局收得下） | 20/20 | 12/12 | 8/8 | 9/9 | 4/4 |
| `0x0060`（恒 28 字节） | 3 | 2 | 3 | 3 | 3 |

`0x0057` 的 +32 是图层号（各图见过 0、1、4、5、6），不是比例。覆盖表里的 f64 是线宽：五张图都只有 **一条 0.18 mm**。把每条 `0x0057` 的对齐 f64 对上 §首的三带，**零命中**。

`0x0060` 七个 u32 是 oid、0、0、集合数、1、1、0。没有浮点。

`0x0076` SheetView 每存储一条，载荷是几百字节的整数和误对齐读出来的巨大值。对齐 f64 没有落进三带（全记录扫描里没有 `0x0076` 的命中行）。

tag 184 是这几条记录之间的边，边上没有比例数。U2 已写明 `TopVFSet` 的持久化不带比例位；本轮文件侧与之相符。

## 3. 页框与符号上的比例

页幅来自 `0x003D` 的 +76 / +84（米）。比例按既有读法是 1:1，字段里没有另存一个 1.67。

| 图 | 页幅（mm） | 长宽比 +148 | 1 / 页宽（米） | 落在 1.67±0.03？ |
|---|---|---:|---:|---|
| 0201 | 594.30504777 × 420.31372525 | 0.70723566 | 1.682638 | 是（差 0.0126） |
| 0202 | 593.74583835 × 419.62916920 | 0.70674882 | 1.684222 | 是（差 0.0142） |
| D06 | 594.32789033 × 420.56569427 | 0.70763244 | 1.682573 | 是（差 0.0126） |
| 工艺管道-1 | 841.00008011 × 594.00004148 | 0.70630200 | 1.189061 | **否**（差 0.481） |
| A01 | 594.00104148 × 420.00101669 | 0.70707118 | 1.683499 | 是（差 0.0135） |

A01 另有一条 0.001 × 0.001 mm、长宽比 1 的框（本地链接的占位，不是页）。

页宽的倒数在四张 A2 上掉进带内，是因为 A2 宽约 0.594 m，1/0.594 ≈ 1.68。字段本身是页幅：工艺管道-1 是 A1，同一个算法得到 1.189，出带。它不是五图共用的 view-scale。

`igSymbol2d` 矩阵标签 `02 00 A7 50` 之后第 7 个 f64（均匀比例）：

| 图 | 条数 | 取值 |
|---|---:|---|
| 0201 | 20 | 全 1 |
| 0202 | 23 | 22 条为 1，**1 条为 0.77993998** |
| D06 | 6 | 全 1 |
| 工艺管道-1 | 58 | 全 1 |
| A01 | 2 | 全 1 |

合计 109 条，108 条为 1，与此前「108/109 为 1」一致。0.77993998 的换算：1/原值 = 1.282150，×25.4 = 19.810475，÷25.4 = 0.030706。三带都不中。这是一个放置自己的比例，不是全图的显示比例。

## 4. `0x002F`：图案之后没有多余字节

判据是 08-07 的帧：`+48` 的 u16 为 N，载荷长度 = 50 + 8N。

| 图 | 条数 | 恰好 50+8N | 图案之后的多余字节 |
|---|---:|---:|---|
| 0201 | 4 | 4 | 无 |
| 0202 | 6 | 6 | 无 |
| D06 | 2 | 2 | 无 |
| 工艺管道-1 | 1 | 1 | 无 |
| A01 | 1 | 1 | 无 |

**14/14 条在图案处截止。** DLL 流尾部那个 f64（成员 `+112`，「比例 / 总长」）没有装在 `.pid` 图案之后。

图案（单位是米，×1000 = mm）与 08-07 相同：`-0.0035, -0.00175`（3.5 / 1.75 mm）、`-0.001905, -0.00127`（1.905 / 1.27 mm，只在 0201 / 0202 / D06）、0202 另有点划、双点划和首段为 0 的点线。

头部 `+26..+47` 不是全零，但里面没有 1.67：

- `+34` 的 f64 随图案变，不随图纸变。3.5/1.75 mm 以及 0202 的点划、双点划是 **0.5**（`+34 = 0`，`+38 = 0x3FE00000`）。1.905/1.27 mm 三条（0201 id 78、0202 id 65、D06 id 36）是 **1.1666666269302368**（`+34 = 0xA0000000`，`+38 = 0x3FF2AAAA`）。0202 那条点线是 **0**。
- 0.5 的换算就是 §1 那一行（2 / 12.7 / 0.019685），不中。1.1666666269302368 的换算：1/原值 = 0.857143，×25.4 = 29.633332，÷25.4 = 0.045932，不中。
- U1 的两族虚线（3.5/1.75 与 1.905/1.27）在这里是 **0.5 和 1.167 两个数**。单一比例 s = 1.67 对不上。
- `+42..+45` 十四条全是 `00 00 00 00`（u32 = 0，低 4 位 = 0）。若这一字就是 DLL 的 `this+104` 标志，模式在五张图、两种图案上都是 0。
- `+46` 是段数再写一遍：N=2 → 131072（2<<16），N=4 → 262144，N=6 → 393216。不是比例。低 4 位随图案变化的是 `+26`（3.5/1.75 mm 为 0，1.905/1.27 mm 为 2，点线为 1），不在 `+42`。

0201 两族虚线所接的 `0x002E`（U2 点名要倒的 `+46` / `+50`）：

| 线样式 id | 虚线 id | 线宽 | `+46` | `+50` | `+26` |
|---:|---:|---:|---:|---:|---:|
| 9 | 8（3.5/1.75，`/JSite329`） | 0.35 mm | 0 | 0 | 2049 |
| 85 | 84（3.5/1.75，根流） | 0.35 mm | 0 | 0 | 2049 |
| 79 | 78（1.905/1.27） | 0.18 mm | 0 | `0x8000` | 2052 |

`+46` 全 0，即 08-04 字段序里的 `this+108`（拟合开关）在这三条上没有置位。`+50` 的 `0x8000` 是电信号线的颜色字，不是比例。

## 5. 基类 `+12` 的单位码：虚线和线宽是同一个 11

单位码不是文件里直接写下的 11/12/13。`style.dll` 读 payload `+12` 的 u16，记作 w，`units = (w & 7) + 10`。先前在全载荷里搜 u16 值 11/12/13 是把编码读反了，那一搜作废；下面只认 `+12` 这一处。渲染时虚线段按 **`0x002F` 自己的**单位码取视图换算因子，线宽按 **`0x002E` 的**（U2 §6）。

| 族 | 0201 | 0202 | D06 | 工艺管道-1 | A01 |
|---|---|---|---|---|---|
| `0x002E` 线 | 29 条，w=1，(w&7)+10=**11** | 37 条，w=1，**=11** | 23 条，w=1，**=11** | 27 条，w=1，**=11** | 20 条，w=1，**=11** |
| `0x002F` 虚线 | 4 条，w=1，**=11** | 6 条，w=1，**=11** | 2 条，w=1，**=11** | 1 条，w=1，**=11** | 1 条，w=1，**=11** |
| `0x0030` 覆盖 | 18 条，w=1，**=11** | 14 条 w=1 → **11**；2 条 w=0 → **10** | 5 条，w=1，**=11** | 9 条，w=1，**=11** | 5 条，w=1，**=11** |
| `0x002C` 文字 | 84 条，w=1，**=11** | 107 条 w=1 → **11**；4 条 w=2 → **12** | 15 条，w=1，**=11** | 34 条，w=1，**=11** | 26 条，w=1，**=11** |

**0x002F 的 (w&7)+10 = 11，0x002E 的也是 11。** 十四条虚线没有一条不是 11。「虚线按自己的单位码走另一套视图换算」这条假设关掉：两边选的是同一个 `styleUnits == 11` 的因子，因子本身不在记录里，记录里也没有 1.67。

**0x0030 的 (w&7)+10：** 53 条里 51 条是 11（w=1），0202 的 2 条是 10（w=0，低 3 位为 0，不在 11/12/13）。那 2 条是样式 id 89 与 140，掩码 `0x80`，`+78` = 0，不是虚线图案的单位码。

两处例外都不是线 / 虚线这对：

- 0202 四条 `0x002C`（样式 id 40、122、123、153）raw = 2，单位码 **12**。文字样式，不参与虚线段。
- 0202 两条 `0x0030`（样式 id 89、140，掩码 `0x80`，`+78` = 0）raw = 0，`(w & 7) + 10` = 10，低 3 位是 0，不在 11/12/13 里。

`0x002E` 的 `+42` 与 **`+46`（`this+108`，拟合开关的 bit0）136 条全是 0**。0201 上 Line2 链和 Electric 也是 0：

| 记录 | 单位码 | `+46` bit0 |
|---|---:|---:|
| 线样式 9 → 虚线 8（`/JSite329`，3.5/1.75） | 11 | 0 |
| 线样式 85 → 虚线 84（根流，3.5/1.75） | 11 | 0 |
| 线样式 79 → 虚线 78（1.905/1.27） | 11 | 0 |
| 覆盖样式 id 48（`/JSite329`，掩码 `0x82`，`+78` = 8） | 11 | — |
| 覆盖样式 id 9（`/JSite396`，掩码 `0x82`，`+78` = 8） | 11 | — |

`0x002F` 头部里，低 4 位随图案变的是 `+26`，不是一个全图常数：3.5/1.75 mm（以及 0202 的点划、双点划）low4 = 0（`+26 = 0x01000000`）；1.905/1.27 mm 三条 low4 = 2（`+26 = 0x01000022`）；0202 点线 low4 = 1（`+26 = 0x01000001`）。`+34` 的 f64 就是 §4 的 0.5 / 1.1667 / 0。两族虚线的模式字和 f64 都不相同，也都不是 1.67。若 `+26` 就是 U2 的模式，3.5/1.75 那族是模式 0（U2：不拟合，只乘当时为 1 的 `ovScale`），更凑不出 1.67。

## 6. `0x0030` 覆盖的比例位

bit2（`+30` 掩码的 `0x04`）才把 `+50` 的 f64 当成比例。五图 18 + 16 + 5 + 9 + 5 = **53** 条，与 10-10 那次的条数相同。**bit2 置位 0 条。`+50`、`+58`、`+66` 全部为 0。** 掩码只有 `0x02`、`0x03`、`0x82`、`0x40000100`。

## 8. 给 U4 的一句

**0x002F 的 (w&7)+10 = 11（14/14），与 0x002E 相同；0x0030 的 (w&7)+10 = 11（51/53），另 2 条是 10。能算出 1.67 的字段：无。** 「虚线另套单位」关掉。

虚线不会因为单位码而去拿另一套视图因子。`0x0030 +50` 五图全 0 且 bit2 未置；`0x002F` 在图案处截止，头部 `+34` 的 0.5 / 1.1667 两族还不相同，`+26` 的低 4 位也是 0 对 2。页宽倒数只在 A2 上凑近 1.68，A1 立刻拆穿。1.67 不在这五张图的字段里（计划 P-D1 的 (b) 那一档）。实作落点留给 U4，本篇不改计划。

## 验证

开跑前没有 `cargo` / `rustc` 进程。只跑了 `cargo run --example`，没有 `--all-targets`。未改 `src`、测试、golden、计划、已有 example。

```text
cd pid-parse
cargo run --example probe_dash_scale_field_candidates
```

exit code **0**（`Finished dev`，然后跑 `probe_dash_scale_field_candidates.exe`）。§1–§7 的条数、图案、`+46 = 0`、bit2 = 0、符号比例、页幅都来自这次输出。

oid 501 与换算用同一次字节读取复核（exit code **0**）：在 `test-file/DWG-0201GP06-01.pid` 里搜索 `00 00 00 3F 00 00 00 3D`，唯一命中在 `0x1602D`，其前 184 字节处 oid = 501、类型字 `0x0114`、`bytes_to_follow` = 358；`+12` 起 8 字节是 f64 1.0。0.5、0.03125、1.1666666269302368、0.77993998 和五张页宽的四种换算是这次 Python 对探针印出的原值做的，进程 exit code 0。

§5 的单位码是另一次只读（exit code **0**）：Python `olefile` 0.47 打开五张 `.pid`，按记录链魔数 `0x6C90F544`、8 字节流头、`类型字 + bytes_to_follow` 走完每条链，对 `0x002C` / `0x002E` / `0x002F` / `0x0030` 读 payload `+12` 的 u16，单位码取 `(w & 7) + 10`。当时已有别的 `cargo` / `rustc` 占着共享 `target/`，这一轮没有再开 `cargo`。example 里的 `unit_codes` 打的是同一张表，留给下次 `cargo run`。
