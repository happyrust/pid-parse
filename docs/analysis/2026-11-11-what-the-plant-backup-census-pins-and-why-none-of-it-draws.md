# 53 张备份图的记录普查钉了什么，每一类为什么不画，证据是什么（2026-11-11）

> 范围：`tests/plant_backup_census.rs` 钉住的每一类记录。
> 用途：完成审计的判据是「没有未解码、被拒、假的、该画没画的记录」。这一页逐类写：钉的是什么、为什么不该画、
> 证据是什么、证据有多硬。**没有证据的写「没有证据」，不写推断当结论。**
> 证据分三种：**文件**（记录自己的字节，可重跑）、**原生读取器**（反汇编读到的行为）、**参考图**（原厂出的 PDF）。
> 53 张备份图里只有与验收语料重名的那几张有参考图；`D04`、`A井场`、`EF井场` 都没有。

## 0. 这道门钉的是什么范围

`tests/plant_backup_census.rs::the_backup_census_is_its_chains_and_the_ef_dot_fills` 读 53 张图的 **`Sheet*` 流**，
钉六样：没有解码器认领的记录（按类型码）、被解码器拒收的记录、原生读取器跳过的记录、`igSmartFrame2d` 条数、
`ComplexString` / Group 条数、链上 `0x0010` / `0x0030` 的条数；另钉 `EF井场` 那颗实心点现在填充。
本机读数（2026-11-11，`9a348ec` 之后）：

```text
plant backup census: 53 drawings …; undecoded {25: 5}, refused {}, 1549 native-skipped over 8 type codes,
51 igSmartFrame2d, 0 of 0x0010 / 0x0030, 1 ComplexString, 0 Group
```

它**不**钉：图内符号缓存（`/JSite*/PSMcluster0`）、模板、`.sym` 库。那三处见 §6。

所以上面每个数的范围都是「53 张图自己的 `Sheet*` 流」。其中 **`refused {}`（被拒 0 条）只在这个范围内成立**：
入库压缩包里四个 `-W` 模板的 Sheet 流上另有 20 条被拒的 `igBoundary2d`（§6），这道门不读它们。

## 1. 没有解码器：`0x0019` × 5（`D04`）

| | |
|---|---|
| 是什么 | `KeyPoint Constraint`（`imagdex.dex`）。`D04.pid` `/Sheet6` oid 196、300、314、456、468，各 34 字节载荷，属主都是 oid 62 |
| 为什么不画 | 它是约束，不是图形：说的是「这条曲线的这个端点与那条曲线的那个端点重合」 |

证据：

- **文件**（这一轮重新读的）：五条都在 `ComplexString` oid 62 的成员表里。载荷 `+18` / `+22` 是两个 oid，
  依次是 (27, 337)、(337, 361)、(361, 380)、(380, 275)、(275, 175)——正是这条串六条曲线的五个接头；其后两个
  `u32` 是各自的端点号（线 0 = 起点、1 = 终点；弧 1 = 起点、2 = 终点，五条都对得上）。被点名的两个端点
  相距不到 4 × 10⁻¹⁴ mm。六条曲线（弧 27、337、380、275，半径 0.8156 mm；线 361、175）各自是链上的活记录，
  各自解码、各自出图。约束说的事，曲线自己的坐标已经说了。
- **原生读取器**：图形谓词 `radsrvitem.dll!sub_56449950` 的常数集（20 个码）里没有 `0x0019`
  （`2026-08-04-annotation-families-risk.md` §2）；类表里这个码的 CLSID 在 RAD 注册表里的名字是
  `KeyPoint Constraint`（这一轮把整张表读了一遍，281 个槽）。
- **参考图**：没有证据。`D04` 没有参考图。

没有做的：`0x0019` 没有解码器，载荷 `+8..+17` 和末尾两个字以外的字节没有逐字段命名。这道门把它钉成
「5 条、没有解码器」，变了会红。

## 2. `ComplexString`：`0x0021` × 1（`D04`）——原来「没有解码器」，现在解码、不发射

| | |
|---|---|
| 是什么 | `ComplexString Object`。`D04.pid` `/Sheet6` oid 62，属主 6，层 65，样式 17；11 个成员（6 条曲线、5 条约束） |
| 为什么自己不画 | 它是关联记录：成员数、一个比例、每个成员 14 字节（oid、范围框、一个字）。里面没有坐标。墨是成员的 |

证据：

- **文件**：成员表逐条解出；6 个曲线成员都是同一条链上的活记录，属主字是 62、层 65、样式 17
  （这道门对 `D04` 断言这一点；`tests/sheet_family_wiring.rs` 对入库的 20 条关联记录断言同样的事）。
  六条曲线首尾相接成一个 2.6 × 7.0 mm 的长圆，在 (161.6, 213.5) mm；最后一个接头（线 175 的终点到弧 27 的起点）
  差 0.0066 mm，没有约束。
- **原生读取器**：图形谓词**接受** `0x0021`——它是图形对象。所以「不发射」的依据不是「它不是图形」，而是
  「它的图形就是它的成员」。
- **参考图**（2026-11-11 补，同类的另外三条串；`D04` 自己没有参考图）：验收的 A2 那张（`轻烃分离器I`）穿
  `CPECCHB-SQ-A2.igr`，这个模板的 `/Sheet6` 上有三条 `ComplexString`——图框和标题栏的边线。
  `pid-plot/examples/probe_what_the_reference_prints_where_a_complex_string_is` 按成员记录的字节范围在页面上找到每条
  曲线成员画出的图元，沿每个成员两侧各 0.4 mm 的走廊读原厂参考图与我方的页：

  | 串 | 成员条目 | 曲线成员 | 成员的笔画 | 参考图沿成员方向的墨 | 走廊里参考图的墨 / 我方盖住的 / 没盖住的 | 走廊里参考图的填充轮廓 / 文字 |
  |---|---:|---:|---:|---|---|---|
  | oid 32（图框，四条线）| 8 | 4 | 1 914.747 mm | 4 笔、1.355 mm 的笔、共 1 914.821 mm（读图器当「页边线」单列的那一类；我方同样 4 笔 1.355 mm、1 914.747 mm）| 592.541 / 592.541 / **0.000** mm | 0 / 0 |
  | oid 49（标题栏外沿，三条线）| 5 | 3 | 302.626 mm | 302.599 mm，一种笔宽（1.016 mm）| 309.585 / 309.585 / **0.000** mm | 0 / 0 |
  | oid 67（两条线）| 3 | 2 | 309.697 mm | 309.711 mm，一种笔宽（1.016 mm）| 322.055 / 322.055 / **0.000** mm | 0 / 0 |

  读法：每条串的每个曲线成员，参考图沿它画了**一遍**（长度与成员相差不到 0.08 mm，只有一种笔宽——若原厂把整条串
  再画一遍，会读到两倍长度或第二种笔宽）；走廊里参考图的墨全部被我方的墨盖住（比成员多出来的那部分是搭在边线上、
  与边线重合的其他家具线，两边都画了），我方也没有参考图没有的墨；没有填充轮廓，没有文字。图框的四条线超过页边
  九成长，`read_plot` 把这种笔画从两页的墨里都拿掉、另列为页边线（`sheet_edge_mm`），所以它们是从
  `read_plot_pens` 读的：参考图在四个走廊里恰好四笔，没有宽度为 0 的填充轮廓——图框围住的区域没有被填充。

  这是「原厂画一条串，画的就是它的成员」的参考图证据，范围是这三条：都在模板上，成员全是直线；图框那条是四条线、四个接头的一圈，另两条是开口的。

**仍然只是推断的**：

- `D04` 的那一条本身（四段弧加两条线的长圆，带 5 条约束）：没有参考图。它与上面三条同类、同语法，结论是按类推过来的；
  「成员是弧时原厂也只画成员」没有参考图样本。
- 笔的两端与拐角：上面读的是笔画的中心线与长度，量不到端头和拐角的画法（平头、斜接还是分别起落）。一条串的
  成员在拐角处是「连成一笔」还是「各画各的」，在 0.4 mm 的走廊里分辨不出；那是按墨读的门禁管的事。
- 这条串自己在线型索引里解析不到样式（样式 17 是成员共用的），成员表之外的字节（`+18` 三字节、条目末尾那个字）
  没有解。

## 3. 被拒收：53 张图的 Sheet 流上现在是 0 条（入库模板上另有 20 条，见 §6）；原来的 `0x00FA` × 1（`A井场`）

| | |
|---|---|
| 是什么 | `Dependency Object`（`imagdex.dex`）。`A井场` `/Sheet6 +251219` oid 46838：36 字节，成员数为 0 |
| 现状 | `c719b0e` 之后解码（原来的解码器要求成员数至少为 1）。这个族 53 张图上有 55 414 条，全部解码、不发射 |
| 为什么不画 | 依赖关系的两端（两个 oid 引用加一个收尾块），没有坐标字段 |

证据：

- **文件**：这条记录的 36 字节按该族自己的语法读通，成员数 0。族的布局里没有坐标：载荷是 oid、属主、
  种类字、子类型字和引用表（`raw_reference_payload`，引用表与收尾块原样保留，**没有逐字段命名**）。
- **原生读取器**：类名 `Dependency Object` 由类表加 RAD 注册表给出
  （`2026-08-04-psm-type-code-registry.md`）。但图形谓词**接受** `0x00FA`。这一条与「它不画」是相抵的，
  照实写在这里：谓词说它属于「图形元素」那一组，谓词本身没有说它有墨。
- **参考图**（间接）：11 张验收图的 Sheet 流上有这个族的记录，我方一条都不画；这 11 页里除 A2 那张外的十页
  对参考图 `coverage 1.000000`、`uncovered 0.000 mm`（`reference_plots_acceptance`）。这十页上原厂的墨没有
  一段要靠 `0x00FA` 来解释。A2 那张的未覆盖墨没有逐段归到记录上，这里不引它作证据。
- 对 `A井场` 这一条本身：**没有直接证据**（没有参考图）。它与其余 55 413 条同族、同语法，成员数为 0。

## 4. 原生读取器跳过的：1 549 条

| 类型码 | 条数 | | 类型码 | 条数 |
|---|---:|---|---|---:|
| `0x004D` 文字 | 640 | | `0x00CE` 符号放置 | 98 |
| `0x00FA` 依赖 | 370 | | `0x003D` 页框 | 74 |
| `0x005E` 点 | 163 | | `0x0018` 线 | 46 |
| `0x0084` 折线 | 157 | | `0x0059` 圆 | 1 |

为什么不画：类型字带 `0x8000`。证据：

- **原生读取器**：`PSMSerializeIn`（`radsrvitem.dll` `0x564915E0`）读到类型字 `0x8000` 置位就 seek 过整条记录，
  连 oid 都不读（`2026-05-14-radsrvitem-psm-serialize-bytes.md`、
  `2026-09-28-the-native-reader-skips-a-flagged-record.md`）。对它来说这不是一个对象。
- **文件**：1 549 条里 842 条在同一条流的后面有同 oid 的活记录（旧副本）；**707 条没有**——被删掉的对象。
  所以「它们是旧副本」只对 842 条成立，文件本身说明不了另外 707 条「已退役」。
- **参考图**：`probe_does_the_reference_print_a_retired_record` 把 11 张验收图 `.pid` 里的 237 条带位记录当作
  活记录解码、放上页、对参考图逐 0.25 mm 取样：「参考图画了、我方没画」= **0 条**
  （`2026-11-07-every-undrawn-record-of-the-plant-backup-is-inkless.md` §4 的分类表）。
- 对 53 张备份图上这 1 549 条本身：参考图的证据只覆盖验收图的 237 条（两个语料是同一套图的不同版本，
  **哪些是同一条记录没有逐条对过**）。其余靠原生读取器的那条规则。

## 5. 同一道门钉的另外四样

- **`igSmartFrame2d` × 51**：解码、不发射。它是 OLE 页框，给出页幅和图纸在页上的位置；它链接的 `.igr` 作为
  模板单独出图。证据：`pid-plot/tests/border_template.rs` 在验收页上把模板的边框、标题栏、会签栏从 PDF 读回来；
  三张没有图框的图按名字钉住。
- **链上 `0x0010` / `0x0030` × 0**：这两个类型码在任何 Sheet 链上都没有记录。读它们的三个族在第四轮退役
  （§17.2 of `2026-11-10-what-the-sixty-unreferenced-pages-leave-undrawn.md`）；第四个无链族 `GLine2d`（`0x3FE6`，
  连类型码都不是）在第五轮退役，四个匹配器从库里挪到了测试一侧（同一文档 §18）。
- **Group × 0**：53 张图的 Sheet 流上没有 Group；模板里有，是关联记录（同 §2）。
- **`EF井场` 的实心点**：`/Sheet6` oid 52844 填充 `igCircle2d` oid 52772。这是整份普查里唯一一条「有墨而没上页」的
  记录，`27015d9` 修好，这道门钉它现在是一个 26 点的填充环。它出墨的依据是同族同写法（1 449 条图纸侧边界和
  缓存体里 159 条 `0x73` 圆成员边界在参考图上印成实心）；`EF井场` 自己**没有参考图**。

## 7. 一句话的结论，分条

- **未解码**：Sheet 流上 5 条 `0x0019`，是约束，文件证据完整；没有参考图。
- **被拒**：53 张图的 Sheet 流上 0 条。**判据若包含入库模板，则有 20 条**（`-W` 模板的徽标填充），没有页面用到。
- **假的**：0 条（链上解码 + 类型字绊线 + 四个无链族退役 + 页框的高宽比）。
- **该画没画**：53 页上已知的 0 条。`ComplexString`「只画成员」现在有参考图证据，但证据来自 A2 模板上的三条
  （成员全是直线），`D04` 那一条本身是按类推的；`A井场` 那条零成员依赖、707 条没有活孪生的被删记录，这两处
  **没有参考图证据**，靠的是文件与原生读取器的规则。
