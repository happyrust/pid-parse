# 最后 98.4 mm 的多画是什么：格点、拼接与两条方向不明的弧（2026-10-20 量）

隔膜执行器的弧盖翻正之后（`2026-10-20-the-actuator-dome-is-on-the-wrong-side.md`），
五张图的多画从 147.3 mm 落到 98.4 mm，残差表里最大的几堆换成了球阀（I 图 12.0 + 12.0）、
超声流量计（10.5）、放空（5.8）。这一轮把它们逐条追到根，结论是**没有一条是画错了**：
参考图的坐标被量化到 1/300 英寸格点、对比器把球阀的两条共线斜边拼成了一条穿过球心的线、
另有两条弧的方向在记录里读不出来。每条都给出复现方式。

## 一、参考 PDF 的坐标在 1/300 英寸格点上

I 井场参考图 45 164 个线段端点坐标，对 `25.4/300 = 0.084667 mm` 取余：

```text
samples 45164  median err 0.0046 mm  p99 0.0047  max 0.0047
```

即**每一个端点都落在 300 dpi 格点上**（偏差就是 pt→mm 换算本身的舍入）。我方按精确
毫米出图，端点不在这张格上，于是同一个 45 格长的笔画在参考里可能落成 44 格或 46 格：

| | 我方 | 参考 | 差 |
|---|---:|---:|---:|
| 球阀法兰竖线长 | 3.810 | 3.725 | 1 格 = 0.085 |
| 球阀球心 y | 381.345 | 381.255 | ≈1 格 |

这条解释了残差里所有 0.1 mm 量级的偏移，也说明**逐像素相同是不可能的**：参考的每个
端点最多能被我方的精确值差半格（0.042 mm），落在同一个符号上会累计。盖（Cap）的五条
实例就是例子：参考弧 0.7°→179.4°，我方 0.2°→179.8°，差在两端各半格。

## 二、球阀的 24 mm 是对比器拼出来的，不是多画的线

`split_extra` 的采样点是沿 `join_centerlines` 之后的线走的，而那个拼接把同一条直线
上相距 3 mm 以内的两段并成一段。球阀的蝶形两腰本来就共线，被球隔开 2.535 mm：

```text
我方：(237.061,379.440)->(234.386,380.778)  与 (232.116,381.913)->(229.441,383.250)
      同一斜率 -0.5，端点相距 2.535 mm < JOIN_GAP 3.0 -> 拼成一条穿过球心的线
参考：同样两腰被格点量化成斜率 0.5 与 0.438，点积 0.9998 < 0.999 的阈值 -> 不拼
```

于是拼出来的那条线在球体内被采到三个 0.5 mm 样本，各记 0.5 mm；两条腰 = 3.0 mm；
图纸上共四个 Type 1、四个 Type 2 球阀命中，正好 12.024 mm 一堆，两种型号数值一模一样
就是这么来的。**图本身没错**：把参考和我方在同一位置按 16 px/mm 渲染对比，蝶形、球、
两道法兰、位号都对得上。

复现：`pid-plot/examples/diagnose_symbol_residual` 的 `pdf` 模式只会列出漏画 > 0.6 mm
的单条笔画，这类 0.15 mm/条的弥散残差要按符号归堆才看得见 —— 或直接看
`plot/compare/*.json` 的 `extra_outside_by_symbol`。

## 三、x≈551.78 的 13.01 mm 是虚线相位，不是多余的线

`diagnose_symbol_residual` 把 I 图最大的一条残差记成
`(551.78,193.26)->(551.78,561.47)` /Sheet6，看起来像一条参考里没有的长竖线。实际两侧
都有一条虚线仪表信号柱，范围都是 y 141→712 mm：

| | 虚线柱 x | 范围 |
|---|---:|---|
| 参考 | 551.69 | 141.14 … 712.31 |
| 我方 | 551.78 | 140.48 … 712.29 |

参考那 13 mm 是**划线相位**的账：同一段虚线，参考在 PDF 里落成 182 段，我方落成 6 段
带 `[5.4 3.6]` dash 的长划；两边相位不同，`diagnose` 按单笔算 uncovered 就把相错的那截
记到这条线上。`compare` 的总账里没有它 —— `extra_outside_by_symbol` 只有球阀、超声
流量计、放空、井口四堆，合计正好等于 `extra_length_mm`，说明逐点采样时它算作覆盖。

## 四、两条弧的方向在记录里读不出来

弧的约定是"从 `startAngle` 顺时针扫到 `endAngle`（`start/end` 是绝对角）"，并归一化到
≤ π 的 minor 弧。把 I 图上每一条画出来的弧都拿去和参考对（同一圆心、同一半径，沿我方
半边与对侧半边各采一遍，看参考的墨在哪边），24 条有明确方向的弧**全部**符合现行约定：

| 符号 | 弧 | 记录 start→end | flag | 参考在哪边 |
|---|---|---:|---:|---|
| Parametric Manifold | 左端帽 | 270°→90° | 0 | 顺时针（左）✓ |
| Parametric Manifold | 右端帽 | 90°→270° | 0 | 顺时针（右）✓ |
| Cap | 半圆 | 90.2°→269.8° | 1 | 顺时针（上）✓ |
| Check Valve | 两腰小弧 | 240.1°→225.1° / 66.8°→81.8° | 0 / 1 | 顺时针 15° ✓ |
| Breather | 弧 | 157.4°→22.6° | — | 顺时针 ✓ |
| DCS 盒 | 两个半圆 | 0°→180° / 180°→0° | — | 合成整圆，不裁 |
| **Local Vent** | 顶盖 | 88.2°→273.4°（顺时针 174.7°） | 1 | **逆时针 185.3°** ✗ |
| **FT-Ultrasonic** | 波形的左半 | 180°→0° | 0 | **逆时针（下）** ✗ |
| **FT-Ultrasonic** | 波形的右半 | 180°→360° | 1 | 顺时针（上）✓ |

两条弧的失败方式互相矛盾，所以**不能靠规则修**：

- FT 的上下两条记录除 `+58` 那一个字节（01 / 00）以外逐字节相同。若"flag 1 = 顺时针"，
  右半对、左半错；若"flag 0 = 顺时针"，正好反过来。
- Manifold 两个端帽的 flag 都是 0，参考却按顺时针画在左右两侧 —— 于是 flag 既不是
  "0 = 顺时针"也不是"0 = 逆时针"。
- Local Vent 要的是**比半圆多 5.3°**的那一侧，即"按记录顺序逆时针扫 185.3°"。而同样是
  `start < end` 的 Manifold 右端帽要的是顺时针 180°，Cap 要的也是顺时针 180.4°。

也就是说：现行"顺时针 + 折回 minor"能对上 24 条里的 24 条、8 条接近半圆里的 6 条，
只剩 Local Vent 和 FT 波形；任何单条规则都会先破掉 Manifold 或 Cap。剩下的可能是
参考出图时用的那份 `.sym` 与 `Ref/Symbols` 快照不同（球阀也是同样的 1 格差），
这需要一份能确定方向的证据（例如带这两件符号的 `.igr` 或另一张参考图），本轮不猜。

复现：

```text
cargo run --example probe_arc_payload_bytes -- "<symbol.sym>"     # 每条 0x0061 的完整尾字节
cargo run -p pid-plot --example dump_symbol_primitives -- "<图名>" "*"   # 纸面弧的世界角
```

`dump_symbol_primitives` 是本轮加的：按符号名（或 `*`）打印纸面图元，残差表里的任何
一堆都能一眼看到它对应哪条记录。

## 五、试过但不成立：收紧 JOIN_GAP

既然球阀的 24 mm 来自拼接，把 `JOIN_GAP_MM` 从 3.0 收到 0.05 应该只会减少假多画。
实测五张图（`compare` 直接重跑，不重出图）：

| 图 | 3.0 覆盖率 / 多画 | 0.05 覆盖率 / 多画 |
|---|---|---|
| I | 0.9989 / 41.8 | 0.9984 / 42.4 |
| A | 0.9998 / 7.6 | 0.9994 / 4.5 |
| B | 0.9979 / 1.5 | 0.9975 / 4.5 |
| 低温 A | 0.9986 / 22.9 | 0.9985 / 20.4 |
| 换热器 CD | 0.9993 / 24.6 | 0.9985 / 42.2 |

覆盖率五张全降、多画三张反升 —— 参考侧同样靠拼接补缝，收紧后两边的"实线"都变短。
拼接阈值维持 3.0 mm，球阀那 24 mm 记录为本轮测量口径的已知代价。
