# `0x0030 JStyleOverride` 指向几何：第一个通过预测的候选

> 日期：2026-08-04
> 范围：`pid-parse`
> 结论类型：**候选成立但链路未闭合**；另附一条对现有解读的质疑。
> 前置：`2026-08-04-geometry-to-style-link-negative.md`
> 工具：`examples/probe_jstyleoverride_link`

## 1. 为什么它的预测和前三个候选不同

前三个候选（Dependency Object / `sub_type_word` / `index`）都是按「**逐线 id 字段**」
去验的，判据是**覆盖率要高**。

`JStyleOverride` 的语义决定了它的预测**相反**：override 意味着几何正常走默认样式、
**只有例外才写记录**。所以它应当

- **只覆盖少数实体**（覆盖率低是通过，不是失败）；
- 但在**固定偏移**上点名一个几何对象（偏移散乱仍然是失败）。

先写下预测再看数据，这样「覆盖率低」就不会被事后解释成两种结果都算赢。

## 2. 实测：`+50` 在两张图上都点名几何

`0x0030` 在 Sheet 流里存在（Sheet 流不是纯记录链，需滑窗扫描；StyleCluster 里也有，
走链即可）：

| 图 | `/Sheet6` | StyleCluster 各流 |
|---|---:|---|
| DWG-0201 | 20 | 11 + 3 + 4 |
| 工艺管道 | 47 | 1 + 6 + 2 |

payload 长度 128 / 129 / 145 / 224 / 225。

**唯一一个在两张图上都稳定点名已知几何 OID 的偏移是 `+50`：**

| 图 | `+50` 命中 | 指向的族 |
|---|---|---|
| DWG-0201 | **17/20** | igLine2d, igPoint2d, igSymbol2d, igTextBox |
| 工艺管道 | **32/47** | igLine2d, igLineString2d, igSymbol2d, igTextBox |

同一偏移、两张无关图纸、指向的全是可绘制族。**这是几何指针。**

覆盖率方面：DWG-0201 20 条 override 对 203 个已知对象，工艺 47 条对 377 个。
**少数派，符合预测。**

## 3. `+58` 是一个跨图纸相同的小枚举

| 图 | `+58` 取值 | 命中 |
|---|---|---|
| DWG-0201 | `{0, 8, 12, 17}` | 15/20 |
| 工艺管道 | `{0, 8, 12, 17}` | 32/47 |

**两张图完全相同的四个值**——而两张图的样式 id 集合本身是不同的（25 个 vs 23 个，
范围 1..85 vs 1..67）。所以 `+58` **不是样式 id**，更像是「覆盖的是哪一项属性」
的判别码。它之所以被计入「命中 id 集合」纯粹是因为 0/8/12/17 这些小数恰好也在
id 集合内——这正是第 2 号候选栽过的坑。

其余偏移（`+35` `+46` `+64` `+76`）的取值里混着 857853503、1143810111 这类大数，
是把别的字段当 u32 读出来的，不予采信。

## 4. 链路还差什么

**override 的语义决定了它多半不引用样式，而是直接带覆盖后的值。** 如果是这样，
那么被它点名的那少数实体的线宽/颜色就在记录里，而**大多数实体走的默认样式来自哪里
仍然未知**——可能是图层/level、可能是文档级默认、也可能在 `0x0010` 里。

所以现在的状态是：

- ✅ 样式值在哪：`0x002C +42`（字高）、`0x002E +34/+50`（线宽/颜色）
- ✅ override 点名哪个几何：`0x0030 +50`
- ❌ override 覆盖的值在记录里的哪个位置
- ❌ 大多数实体的默认样式从哪来

## 5. 一条对现有解读的质疑

pid-parse 现在把 `0x0030` 解读成**标注锚点**：`JStyleOverrideEmitter` 产出
`PidGraphicKind::Annotation`（inferred），OCS 把它画成 `PID-ANNOTATION` 图层上的
方向短线。DWG-0201 那 20 条就是这么来的。

但这个族的名字是 **JSL Override Style**（style.dll，Phase 16 已经证过 CLSID），
`+50` 又稳定指向几何——**它更像样式覆盖表而不是标注**。Phase 16 Slice F 的注释
本身也承认「payload +0..15 的字段语义在 IDA Version 3 schema 与 probe v5 证据之间
仍然歧义」，anchor 解读是从「这两个 f64 落在 0..1 归一化范围内」推出来的。

**建议**：在 native reader 复核 `JStyleOverride` 之前，不要加深 anchor 这条解读；
OCS 侧 `PID-ANNOTATION` 默认隐藏，所以当前没有可见损害，但这个判断需要复核。
