## 2. 这两条斜线是 stamp 出来的记号，不是记录里的线

打印 primitive 的 `byte_range` 是 `130956..131050`，与 `/Sheet6` 的 `igLineString2d`
（oid 4454，四点链 `(613.94,340.75)→(613.94,370.61)→(664.67,370.61)→(664.67,354.52)`）
同一条记录。两条斜线各 3.59 mm、相距 1.27 mm，正是 `stamp_complex_dash` 的记号字形
（`complex_dash_glyph_span_mm` 的注释：两条平行斜划，沿走向 2.5 mm、横向 2.6 mm，
斜长 3.6 mm）。

沿走向量位置：竖管长 16.09 mm，从 `(664.67,370.61)` 起点算

| | 记号中心 | 距起点 |
|---|---|---|
| 我方 | `y≈365.53` | **5.08 mm** = 样式 advance 10.16 的一半（`complex_dash_positions` 单记号规则） |
| 参考 | `y≈362.55` | **8.07 mm** ≈ 半个 16.1 mm |

横管上的那个记号两边一致到 0.55 mm（我方 45.66 / 参考 46.21 距 `x 613.94` 端），所以不是整段平移。

## 3. 判定

**结论：H1、H2、H3 三条都不成立**（逐条反证见下），真因是第四条 —— 单记号落点规则（§4）。
按计划的停止条件，这里记录反证、不硬凑成因；§4 的施工是用户随后明确要求「继续修复」后做的。

- **不是 H1 放置变换**：窗口里没有符号体（唯一的 `symbol` 是 `Single Function/Disc…` 的
  `circ (664.671,348.169) r 6.350` 仪表圈），两条斜线是 `/Sheet6` 原生记录上的 stamp，没有 `scale`。
- **不是 H2 层过滤**：竖管 16.09 mm 100% 落在参考墨上（最差 0.11 mm），没有被过滤掉的东西。
- **不是 H3「体里没有竖杆」**：竖杆在，且与参考差 0.06 mm。
- 余量真正落在**单记号位置规则**上：本段 16.09 mm ≈ 1.58 个 advance，`complex_dash_cells`
  取 1 格，`complex_dash_positions` 给 `period/2 = 5.08`；参考页给 8.07。

## 4. 修在哪：单记号的落点改为「不早于段中点」

§3 把问题钉在 `complex_dash_positions` 的单记号分支：它给 `period/2 = 5.08`，参考给 8.07。
先补独立证据再动代码 —— `probe_complex_dash_marks` 逐段印出参考页的记号中心（本页 8 段，
另两张 A1 页对照）：

| 管段 | 参考记号中心 | 旧规则 `period/2` | 新规则 `max(period/2, L/2)` |
|---|---|---|---|
| 16.09 mm（`oid 4454` 末段） | 8.07 | 5.08 | **8.05** |
| 16.09 mm（`oid 6916` 末段） | 8.04 | 5.08 | **8.05** |
| 6.19 mm（`oid 1567`） | 5.09 | 5.08 | 5.08 |
| 6.19 mm（`oid 2926`） | 5.14 | 5.08 | 5.08 |
| 6.54 mm（`oid 4394`） | 5.02 | 5.08 | 5.08 |
| 3.83 mm / advance 7.62 | 3.81 | 3.81 | 3.81 |

一条规则同时对上六个读数：短于一个 advance 的管子仍取半个 advance（它们的段中点更靠
起点），长过 advance 的管子把唯一一个记号放到段中点。改动只有一行
（`pid-plot/src/model.rs`：`vec![half]` → `vec![half.max(length_mm * 0.5)]`），单测
`a_lone_glyph_keeps_half_a_period_until_the_run_outgrows_it` 钉住上表六行，外加 20 个
记号长管（首记号 5.09）的回归。

单记号分支本身另有一条专用用例 `a_lone_glyph_past_one_advance_takes_the_runs_centre`：
10.5 / 12.0 / 16.09 / 17.0 mm 四段都只有一格，断言落点是 `L / 2` 且严格大于
`period / 2`（所以 16.09 mm 读 8.045，而不是 5.08），并钉住 `L == period` 是两种口径
相接的地方。把表达式临时还原成 `vec![half]` 跑，这条用例在 10.5 mm 处报
`sits at [5.08]`，与旧用例同时失败；恢复后两条都过 —— 断言不是恒真。

重跑十一张：A1 三张 `extra 8.210 → 0.000 mm`、`coverage 0.9981 → 0.9986 / 0.9987 /
0.9986`、pen 一致数各 +4（两条斜划 × 两端），其余八张读数一条没动。

## 6. 相位没有重启：那 0.7 mm 是探针的重心偏差（2026-11-03 复核）

A0 三张图（I / J K / L M）有 17 段 3.83 mm 的尾段（`seg 2/2`，advance 7.62）。
`probe_complex_dash_marks` 一度把它们读成「参考在 3.04–3.22 mm 打记号、我方在 3.81」，
看上去像复合虚线在折点处丢了相位。直接量参考墨（I 页 `oid 127` 末段）后不成立：

| 参考墨 | 沿管段位置 |
|---|---|
| 竖臂（横跨管段） | t = 2.41 mm |
| 横臂（沿管段，2.54 mm） | t = 2.41 → 4.95 mm |
| 字形锚点（两臂交点） | **t = 3.68 mm** |
| 我方印记 | t = 3.81 mm |

3.04 是探针原来的读数：它把两个臂的中点（2.41 与 3.68）平均成「记号中心」。这个字形是
L 形，两臂中点沿管段相差 0.635 mm（矢跨 2.54 的四分之一），所以该字形的每一枚记号都被
读早 0.64–0.71 mm —— 同一段 63.41 mm 长管上的 8 枚记号全部如此；而三张 A1 的对称斜划
只偏 0.06 mm，不受影响。

逐段重扫十一张（`target-gates/dash-sweep4.log`）：17 段尾管的参考锚点 3.68–3.88，我方
3.81，差 0.00–0.13 mm；其它管段 0.04–0.19 mm，同一量级。相位没有丢，**渲染不改**。

处置只落在探针上，两处修正：

1. **逐笔按臂取中点**，不再用整枚字形的均值。参考页并不总印出全部臂：横向臂压在管壁上
   时会与壁墨合并，读回来的只有沿段那一笔（L M `oid 2861` 每枚记号只剩一条 2.54 mm
   横划），整枚均值就凭空减掉 0.635 mm。现在每一笔按方向与长度匹配到它自己那一臂，取该
   臂的沿段中点；方向并列（CD 的平行双划）取候选臂均值，正好是这对斜划自己的中心。
2. **侧向窗按字形自身横向跨度**（widest local y + 0.25 mm），不再固定 2.2 mm。相邻管壁
   的沿段臂距本管只有 ~3.4 mm，旧窗把它收进来，八枚记号的簇心被拖成 7.62–8.07 的不规则
   间距（J K `oid 33010` 读差 0.36）。

改后 A1 的 8.07 / 8.04 不变，I 页 3.83 尾段仍是 3.68 对我方 3.81；全语料 134 段的最大差
从 0.69 降到 **0.19**（`target-gates/dash-sweep5.log`），计数不一致仍为 0。剩余
0.10–0.19 是参考侧自身的笔画截断与拖动，读数以验收门的 coverage 为准。

## 8. done-when 措辞与停止条件（2026-11-04 接受）

后一次执行指令的 done-when 写成「H1、H2、H3 中恰好一条被证据确认，并按该条施工」。
实测三条都不成立，真因是计划没有列出的单记号落点（§4）。同一份计划的停止条件写明：
三条都不成立就停在阶段 1，记录反证，不硬凑成因。§3 按停止条件记录，不把已被反证
否掉的假设认领成「那一条」。done-when 的那句以停止条件为准，到此闭合。

渲染修复与三处 `Pin` 收紧不在该停止条件的授权里。`1a1946d` 已按「不改渲染」收口；
用户随后说「继续修复」，才有 `570e01b` 的 `half.max(length_mm * 0.5)`，以及
`extra 8.210 → 0.000`、coverage 收到 `0.9984 / 0.9985 / 0.9984`。这次接受，不回退：
§4 的六段参考中心与这一条规则对齐，短管与其余八张读数保持，A2 的 210.712 mm 未动。

### 7.1 更正（2026-11-06）：那圈「波形」是两只风机椭圆，`.sym` 和缓存体都有

§7 的表只数了 `igLine2d`。`Air Cooler Type 1.sym` 的 `Sheet6` 另有两条 type
`0x0063`、59 字节的记录（`+344` oid 726、`+633` oid 764，layer 5；`Sheet760` 同两条），
是 `igEllipse2d`（「Ellipse Object」，CLSID `A3494010-D3E1-11CD-8AEA-08003601B44A`），
此前没有任何解码器读它。payload：`+18/+26` 圆心，`+34/+42` 长半轴向量，`+50` 短/长比，
`+58` 标志字节。读数：圆心 `(66.225, 13.970)` / `(70.935, 13.970)` mm，长半轴 2.355 mm，
比 0.44813（短半轴 1.055 mm），每只周长约 11.10 mm。符号插入点映射后落在页面
`(238.43, 466.52)` / `(243.14, 466.52)`，正是参考那 40 段短划的位置。`RefData~4~681.zip`
中的同名 `.sym` md5 相同；三张 A1 `.pid` 的缓存体 `PSMcluster0` 也各有这 2 条。所以这是
**我们漏解码**，不是参考侧版本差。

修复：`decode_igellipses` / `decode_igellipse_at`（`src/parsers/sheet_records.rs`），
`.sym` 读取（`symbol_library.rs` `TYPE_ELLIPSE`）与缓存体（`JSiteNestedGeometry::ellipses`
→ `embedded_symbol_definitions`）都把它画成整圈有理 B 样条。三张 A1 读数：

| | 修复前 | 修复后 |
|---|---|---|
| uncovered | 23.031（8.932 + 8.342 + 5.757） | 5.757（仅 `/Sheet6`） |
| coverage | 0.998649 / 0.998660 / 0.998636 | 0.999662 / 0.999665 / 0.999659 |
| pen 一致 | 3199 / 3206 / 3078 | 3241 / 3248 / 3120 |
| extra | 0.000 | 0.000 |

其余 8 张读数逐位不变。剩下的 5.757 mm 是 `/Sheet6` 上 0.1–0.3 mm 的划线端头（2.032 mm
划段的边沿），与 `docs/analysis/2026-11-04-the-five-uncovered-remainders-are-dash-tips.md`
同类。复现：`cargo run --example probe_sym_ellipse_records -- "<.sym 或 .pid>"`。
